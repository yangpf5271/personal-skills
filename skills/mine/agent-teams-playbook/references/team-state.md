# 团队状态落盘

仅在任务允许写入，并且需要跨会话恢复、多阶段交接或长期跟踪时读取。用户要求只读或禁止修改文件时不得使用本流程。

## 目录

```text
.team/
├── plan/       # task_plan.md / findings.md / progress.md
├── reports/    # 获准落盘的成员报告
├── shared/     # 允许互见的交换产物
└── private/    # 约定限读的暂存产物，不提供访问控制
```

`.team/` 只存协作元文件，真实代码和配置写入拆分计划指定的业务路径。创建、文件用途、保留/提交/清理范围必须写入拆分计划并随唯一启动确认一并确认；默认不提交 `.team/`，是否保留、提交或删除由用户决定。

## 模板

从以下文件复制所需模板到 `.team/plan/`：

- `templates/task_plan.md`：目标、阶段、角色映射和错误。
- `templates/findings.md`：重要发现和技术决策。
- `templates/progress.md`：阶段进度和验证结果。

> 模板内的 5 阶段（需求与发现/规划与结构/实现/测试与验证/交付）是通用项目骨架，与本手册的四阶段流程不必一一对应；按实际任务阶段填写。

只创建任务实际需要的文件。每个阶段开始前读取计划，完成后更新状态。恢复会话沿用原拆分计划与确认（原确认覆盖计划内成员重建）；计划变更时按 SKILL.md 走“重新设计”。

## 交接

- 大产物留在声明路径，消息只发送路径和一句摘要。
- `private/` 依赖 prompt 约束，不是安全边界；独立评审优先让成员直接返回协调器。
- 成员仍可接收消息时，原始观点优先经协调器转交；成员完成即自动结束的平台，在互见阶段重建成员并在 prompt 注入第 1 轮原始观点（不注入协调器判断）；获准落盘时第 1 轮暂存 `private/`，第 2 轮驳论进 `shared/`。
- 成员报告只有在用户允许落盘且后续确需复查时写入 `reports/`，否则直接返回协调器。
