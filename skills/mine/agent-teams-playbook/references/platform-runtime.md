# 平台运行时适配

仅在准备创建、通信、等待或收尾子代理时读取。当前会话实际暴露的工具定义是唯一事实来源；本文件不绑定平台工具名。

## 能力探测

从当前会话工具定义中分别确认：

1. 是否能创建子代理，以及创建参数和并发限制。
2. 消息是仅排队，还是会唤醒并触发新回合。
3. 是否有等待能力，以及等待是否占用并发槽位。
4. 停止能力是中断当前回合、关闭成员，还是释放整个团队。
5. 子代理完成后是自动结束、保持空闲，还是需要显式关闭。

工具不存在时禁用对应动作，不根据历史平台知识臆造调用。工具存在但真实派发失败时，保留原始错误并按下方故障规则处理。

## 并发上限

- 运行时明确给出总槽位时，可并行子代理数 = 总槽位 - 主协调器及其他活跃成员占用。
- 运行时只给出子代理上限时，直接采用该上限。
- 无法获知时，保守地最多并行 3 个子代理。
- 用户可以要求更少，不能通过确认突破平台硬上限。

子任务超过上限时合并同质任务或分批执行；批次切换前先收集上一批最终状态。

## 通信与等待

- 只需排队补充信息时，用不触发回合的消息能力。
- 需要空闲成员继续工作时，用会触发新回合的唤醒能力。
- 没有成员互发能力时，由协调器转发必要信息并告知用户。
- 只有结果阻塞下一步时才等待；等待期间继续推进不重叠工作。

## 生命周期

对每个成员记录 ID、任务、写入范围、状态和收尾结果。

- **完成即自动结束**：记录最终结果，无需额外调用。
- **保持空闲**：停止派发并记录“会话内仍可用”。
- **中断当前回合**：只用于停止正在执行的回合；中断后成员仍存在，不能记为已关闭。
- **显式关闭**：仅当工具定义明确承诺关闭或释放时调用，并记录返回状态。
- **团队级释放**：先满足平台要求的成员收尾条件，再释放团队。

不存在关闭能力时，收集最终状态并停止派发就是可执行的收尾边界，但报告必须如实说明成员未被显式释放。

## 故障规则

| 故障 | 处理 |
| --- | --- |
| 首次派发出现模型、档位、配额或配置错误 | 转述原始错误和可核对配置；用户修正后最多重试一次，同类错误继续出现则改为本地执行或结束 |
| 子代理失败 | 单向模式重新创建并附前次错误；双向模式使用当前会话实际提供的补充输入或唤醒能力 |
| 子代理阻塞或无输出 | 核对输出要求，补充必要上下文；仍无响应则由协调器接手 |
| 通信工具不可用 | 改由协调器中转，不伪造工具调用 |
| 核心技能或环境依赖缺失 | 说明缺失项与影响，提供安装方式交用户手动安装，不未经授权自动安装 |
| 清理失败 | 记录成员 ID、实际状态和失败原因，不宣称已关闭 |
| 上下文溢出或超时 | 缩小任务和输入，分批重新执行 |

同一类型错误连续 3 次后停止重试并升级给用户；配置类错误按上表的一次重试上限执行。
