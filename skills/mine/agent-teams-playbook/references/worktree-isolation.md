# Worktree 隔离流程

仅在写入隔离判定选择 L2 时读取。Worktree 隔离中间状态，但不会消除最终合并冲突。

## 前置条件

1. 确认目标是 Git 仓库，记录主工作树、目标分支和明确的基线提交。
2. 检查主工作树是否存在未提交或未跟踪改动。存在时不得自动提交、暂存、清理或忽略；优先退回 L0/L1，或让用户明确选择可复现基线。
3. 为每个角色生成 ASCII slug，格式限制为 `[a-z0-9][a-z0-9-]{0,31}`。角色显示名不得直接拼入路径、分支或命令。
4. 预先解析每个目标路径，确认它是计划中的仓库同级目录、彼此不重叠，且不是仓库根目录、用户目录或其他宽泛目录。
5. 将基线提交、目标路径、分支名、合并顺序和清理范围写入拆分计划，由用户一次确认。

## 创建与执行

- 使用参数化命令调用 Git，不把路径、slug 或用户文本拼成 shell 字符串。
- 每个成员只在自己的 worktree 和 `team/<slug>` 分支工作。
- L2 prompt 明确允许成员小步提交自己的分支；仍禁止提交到主分支、rebase、force push、修改其他 worktree 或清理路径。
- 需要前序产出时，按拆分计划规定的依赖顺序合并前序分支；未声明的横向合并先回报协调器。
- 协作元文件若获准落盘，由协调器维护在主工作树；成员不在各自 worktree 创建副本。

## 合并

1. 收集每个成员的最终状态、提交列表和验证结果。
2. 合并前重新检查主工作树状态；出现计划外改动时暂停并重新评估。
3. 按依赖顺序逐个合并到用户确认的目标分支。
4. 冲突可机械判定时由协调器处理；涉及行为或产品取舍时保留双方证据并请求用户裁决。
5. 在主工作树运行整体验收，不能用单个 worktree 的通过结果代替。

## 清理

- 只处理计划中登记且已重新解析核对的精确路径和分支，不使用通配符或推导出的宽泛目标。
- 未合并、验证失败或仍含未提交改动的 worktree 默认保留并报告，不强制删除。
- 删除 worktree、分支或协作元文件必须已包含在用户确认的计划中；执行范围发生变化时重新请求授权。
- 清理后检查 worktree 列表、目标分支和主工作树状态，并报告保留项。
