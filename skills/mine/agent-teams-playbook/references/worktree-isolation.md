# Worktree 隔离流程

仅在写入隔离判定选择 L2 时读取。Worktree 隔离中间状态，但不会消除最终合并冲突。

## 前置条件

1. 确认目标是 Git 仓库，记录主工作树、目标分支和明确的基线提交；非 Git 仓库时不适用 L2，退回 L0/L1。本流程面向常规单工作树 Git 仓库；submodule、LFS、sparse-checkout、裸仓库或目标分支已被其他 worktree 检出等形态，先人工确认可行性，否则退回 L0/L1。
2. 检查主工作树是否存在未提交或未跟踪改动，以及被 ignore 的必需依赖物（如 node_modules、虚拟环境、.env——不会随 checkout 进入 worktree，缺失时成员无法自足运行，需在基线选择时安排物化）。存在改动时不得自动提交、暂存、重置、清理或忽略；优先退回 L0/L1，或让用户明确选择可复现基线；用户无法提供基线时按统一出口改选隔离层级或终止并收尾。
3. 为每个角色生成 ASCII slug，格式限制为 `[a-z0-9][a-z0-9-]{0,31}`。角色显示名不得直接拼入路径、分支或命令；slug 由协调器从角色名转写生成（不可转写或冲突时追加角色序号），生成后按上述正则校验，映射关系随拆分计划展示。
4. 预先解析每个目标路径，确认它是计划中的仓库同级目录（布局形如 `../<repo>-<slug>/`，与主工作树并列）、彼此不重叠，且不是仓库根目录、用户目录或其他宽泛目录；确认目标路径、`team/<slug>` 分支与目标分支的检出状态均无冲突（目标分支被其他 worktree 检出时，合并阶段会被 git 拒绝，须先解决）；目标路径或分支已占用则更换 slug，清理残留须另行获得用户授权（可列入拆分计划随确认门一并确认）。
5. 将基线提交、目标路径、分支名、合并顺序和清理范围写入拆分计划，由用户一次确认；呈现规格：基线为提交 hash、分支为完整 ref、路径为绝对路径（含父目录可写性预检）。

## 创建与执行

- 使用参数化命令调用 Git，不把路径、slug 或用户文本拼成 shell 字符串。
- 从确认的基线为每个成员新建 worktree 与 `team/<slug>` 分支（`git worktree add <path> -b team/<slug> <基线>`），成员只在其中工作。
- L2 prompt 明确允许成员小步提交自己的分支；仍禁止提交到主分支、rebase、force push、修改其他 worktree 或清理路径。
- 需要前序产出时，由后序成员在自己开工前或前序交付后，把拆分计划声明的前序分支合并进自己的分支；只合并声明的前序分支，未声明的横向合并先回报协调器。
- 后序成员执行级联合并时的冲突：机械冲突由该成员自行处理并在返回中记录；涉及行为或产品取舍的回报协调器，按合并节的归属原则升级，不得静默选择一方。
- 分支一旦被后序成员吸收（其提交进入后序分支历史）即冻结：不得再 reset、amend 或以新实例从基线重建替换；确需变更时按“废弃原分支 + 通知已吸收它的后序成员重做”处理。
- 成员重建或换代时先移除其旧 worktree（分支保留），再用原分支新建 worktree（`git worktree add <path> team/<slug>`，不带 `-b`）——已有提交全部保留，重建以继续而非重来推进；仅当原分支不可用且尚未被后序成员吸收时，才从基线新建并全量重做，该决定写入计划。
- 协作元文件若获准落盘，由协调器维护在主工作树；成员不在各自 worktree 创建副本。

## 合并

1. 收集每个成员的最终状态、提交列表和验证结果。
2. 合并前重新检查主工作树状态（含其当前分支是否为目标分支）；出现计划外改动（含任务开始前已存在的未提交改动）时暂停并按统一出口处理：机械冲突由协调器处理，无法判定或影响基线时交用户裁决。
3. 按依赖顺序逐个合并到用户确认的目标分支。
4. 冲突可机械判定时由协调器处理；涉及行为或产品取舍时保留双方证据并请求用户裁决。
5. 在主工作树运行整体验收，不能用单个 worktree 的通过结果代替。

## 组合场景

- **分阶段编排**：阶段验收可在成员 worktree 内执行，最终整体验收必须在主工作树；worktree 与分支默认跨阶段保留（任务窗口 = 整个任务），阶段边界不合并、不清理，除非计划另有声明。
- **辩论模式**：互见阶段重建成员时沿用其原 worktree 与分支（同资源继承规则），第一轮的小步提交得以延续。
- **协调器会话中断**：恢复时先枚举现存 worktree 与 `team/` 分支，映射进重建计划后再继续推进；游离对象按清理节的登记与授权流程处理。
- **批量 fan-out**：默认逐批前移基线——前批合并到目标分支后再为下一批建 worktree（写入计划的基线策略字段，随确认门确认）；批间保持串行。

## 清理

L2 分支生命周期绑定任务窗口：合并或废弃后即清理，不留下游离分支。只处理计划中登记且已重新解析核对的精确路径和分支，不使用通配符或推导出的宽泛目标。

- 用户明确放弃某成员产出时可整体废弃：删除其 worktree 和 `team/<slug>` 分支；其提交若已被后序成员吸收，不随删除消失——按冻结与废重规则处理受影响分支。
- 未合并、验证失败或仍含未提交改动的 worktree 默认保留并报告，不强制删除。
- 删除 worktree、分支或协作元文件必须已包含在用户确认的计划中；执行范围发生变化时重新请求授权。
- 任务缩小或失败回退而不再需要 L2 时：已建的 worktree 与分支按本节流程销账（合并或废弃），更新计划后继续。
- 清理后检查 worktree 列表、目标分支和主工作树状态，并报告保留项。
