# 确定性流水线编排

仅在当前会话明确提供确定性流水线能力，且用户已显式 opt-in（明确要求使用确定性流水线即视为 opt-in）时读取；为设计复合任务的流水线子块方案可先读编排语义，提交流水线前仍须满足 opt-in。显式流水线意图即使未提及多代理，也先经 SKILL.md 的流水线路由。实际工具名、脚本结构、参数和进度接口全部以当前会话工具定义为准；本文件只规定编排语义。流水线能力缺失或启动确认被拒时，回到 SKILL.md 的“触发与路由”重新选择执行方式；已产生业务产出后按批次熔断处理（停止未开始项、在途项按生命周期收尾，向用户说明并选择协调器接手或终止），不回到初始路由；路由阶段即发现能力缺失时直接走该阶段的降级确认，无需回环。

## 流程

1. **能力确认**：确认工具定义包含批量子任务与结构化返回能力，缺失则回到 SKILL.md 的“触发与路由”；进度观测不可用时按步骤 5 执行。
2. **纳入唯一确认**：将 fan-out 结构、质量模式、写入范围、预算和降级路径纳入 SKILL.md“设计与确认”的唯一启动确认，不另设流水线确认门；用户拒绝当前方案时回到“触发与路由”重新选择执行方式。
3. **脚本设计**：确定输入集合、阶段、并行屏障、错误策略和返回 schema。
4. **提交执行**：使用当前运行时提供的确定性编排工具提交，不臆造函数或参数。
5. **进度跟踪**：使用实际可用的进度能力；不可观测时提前说明，不伪造实时状态。
6. **结果汇总**：验证结构化返回和实际文件产出，由主协调器完成验收。批次熔断时停止未开始的派发；在途项按 `references/platform-runtime.md` 的生命周期语义收尾，逐项记录完成、部分完成、失败、跳过或未开始，并按 SKILL.md 的缺口交付规则处理。
7. **资源收尾**：按已确认范围处理临时脚本、worktree 和中间产物；删除动作遵循精确目标和授权边界。

## 控制流选择

| 需求 | 选择 |
| --- | --- |
| 各项可独立流过多个阶段 | 流水线处理，避免全局屏障 |
| 合并、去重或裁决必须看到全部前序结果 | 设置并行屏障后汇总 |
| 输出需要被机器汇总 | 为每个子任务定义结构化 schema |
| 子任务规模不确定 | 按剩余预算和新增发现决定是否扩展 |
| 单项失败不应终止全批 | 返回逐项状态，由协调器决定重试或跳过 |

默认优先无屏障流水线；只有合并、去重、早退或全局裁决确实依赖全部结果时才使用屏障。

## 质量模式

| 任务要求 | 模式 |
| --- | --- |
| 高置信度审查 | 多个独立反证者验证同一结论 |
| 多类失败风险 | 为验证者分配互斥视角 |
| 解空间宽 | 多个独立方案加统一评分标准 |
| 未知规模发现 | 连续若干轮无新增发现后停止 |
| 收尾完整性 | 单独检查遗漏项和未覆盖范围 |

## 与对话式团队复合

主体需要动态协调、其中某个子块适合大规模确定性处理时，对话式团队负责目标、用户交互和动态决策，流水线只负责已冻结的批量子块。子块返回后仍由主协调器纳入统一质量闸门；流水线能力不可用时按 SKILL.md“设计与确认”的分批公式处理。
