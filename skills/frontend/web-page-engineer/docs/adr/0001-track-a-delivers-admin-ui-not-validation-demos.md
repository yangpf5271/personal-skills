# Track A 交付管理系统页面,而非流程验证演示

Track A 初版(SKILL.md v2)把 prototype 技能的验证装置——状态面板、自由操作按钮、引导式 walkthrough——原样搬进了交付物,产物实质是"流程验证 demo"。经讨论重定位:本技能的目标是**生成合格的管理系统页面**,验证流程是 prototype 技能的领域。决定:业务流程逻辑以纯状态机形式**内化为页面控制层**(守卫→按钮启用/禁用+原因提示,状态→视图变体),永不渲染为 UI;界面默认采用**最大权限视图**(全部屏幕与操作区可见,无角色切换);演示能力收纳进**场景面板**(可拖拽圆球展开,一键重置场景与状态速览,收起时不可见)。撤销装置的直接原因是:演示装置与真实管理系统观感互斥,而"合格页面"的验收标准是真实系统观感、状态条件化 UI、真实数据密度、内存 mock 后端。

## Considered Options

- 保留 walkthrough/状态面板作为产物功能 —— 否决:那是流程验证的舞台,不是管理系统页面。
- 模拟登录呈现角色差异 —— 否决为默认:更复杂且评审时看不全;权限差异仅在设计明确要求时经场景面板提供。
