生成后反馈闭环
references/生成反馈闭环.txt ｜ V1.0
════════════════════════════════════════════════════════════

> 解决的问题：分镜交付后→用户生成视频→某些镜头翻车→用户回来找你改
> 你不知道哪个镜崩了、崩成什么样、该改什么参数。
> 本库建立"生成结果→失败归类→修正建议→经验积累"的闭环。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
一、反馈输入接口
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 触发条件：
用户在生成后回来，说出以下任一关键词时激活：
"生成完了"/"出结果了"/"翻车了"/"崩了"/"镜X不行"/"重roll了"/"成功了"
或者用户提供生成截图/描述生成效果时。

■ 输入格式（用户自然语言，不强制结构化）：

用户只需说出：哪个镜 + 结果如何。

示例：
✓ "镜1到镜3都挺好，镜4脸崩了，镜7手指多了一根"
✓ "全部生成了，镜12还行但表情太僵，镜15完全糊了"
✓ "成功，所有镜都没问题"
✓ "镜2重roll了3次还是穿模，角色衣服和背景融为一体了"

■ 内部解析规则：
1. 提取镜号 → 匹配 shots_locked.json 中的镜头
2. 提取结果状态 → SUCCESS / PARTIAL / FAILED
3. 提取失败描述 → 匹配失败模式关键词表（见第二节）
4. 无明确描述 → 问用户一句"具体什么问题？（脸/手/动作/穿模/颜色/其他）"

二、失败模式自动归类
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 失败模式关键词表（对接生成检查与规避库.txt SECTION:B）：

| 用户描述关键词 | 失败类型 | 对应规避库SECTION | 修正策略索引 |
|--------------|---------|-----------------|------------|
| 脸崩/脸歪/五官融化/脸糊了/换脸 | 面部崩坏 | 一.1 人物数量类 | §三-1 |
| 特效遮脸/法阵糊脸/光盖住了 | 遮挡类 | 二.1 特效遮挡 | §三-2 |
| 多指/六指/手指粘/手畸形/手部穿模 | 手部失败 | 三.1 手部复杂度 | §三-3 |
| 动作不连贯/动作糊/看不清动作 | 动作模糊 | 四 动作复杂度类 | §三-4 |
| 颜色串/颜色不对/衣服变色 | 色彩漂移 | 五 色彩串味类 | §三-5 |
| 空间跳变/位置变了/站位乱了 | 空间断裂 | 六 空间类 | §三-6 |
| 风格不对/不像漫剧/变卡通了 | 风格漂移 | 七 风格漂移类 | §三-7 |
| 人物瞬移/凭空出现/消失 | 角色异常 | 一.2 群像类 | §三-1 |
| 穿模/衣服融背景/物体穿过身体 | 穿模 | 六.2 穿模类 | §三-6 |
| 表情太僵/面瘫/没表情 | 表情失败 | （微表情库对接） | §三-8 |
| 其他/说不清楚 | 未分类 | 人工分析 | §三-9 |

■ 归类流程：
1. 扫描用户描述，匹配上表关键词
2. 多关键词命中 → 取第一个 + 记录其他作为次要失败类型
3. 未命中任何关键词 → 列出10类让用户选
4. 匹配成功 → 进入修正建议生成

三、修正建议自动生成
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

每个失败类型对应一套标准修正流程：

§三-1 面部崩坏（多人物导致）
诊断：画面清晰人物超过模型配额
修正：
  a. 减少清晰人物数：第三人起降层（虚化70%+ / 剪影 / 色块）
  b. 拆镜：3+人对峙→拆为2人+反应镜交替
  c. 加负面词："多人物, 面部混淆, 特征串味"
  d. 查规避库一.1 获取正反例参考

§三-2 遮挡类（特效/前景遮脸）
诊断：发光特效或前景遮挡覆盖面部
修正：
  a. 特效位置移至安全区：脚下地面 / 身后背景 / 掌心前方（与面部错层）
  b. 加保险词："面部干净，无符文投影，无遮挡"
  c. 前景遮挡限制5-15%画面+虚化60%+
  d. 查规避库二.1 获取正反例参考

§三-3 手部失败（多指/畸形）
诊断：手部动作复杂度超过模型能力
修正：
  a. 手部动作降级：查规避库三.1降级表（十指结印→并指前点）
  b. 简化为单手动作或藏手（手在身后/口袋/握拳）
  c. 加负面词："多指, 手部畸形, 手指粘连"
  d. 关键手部特写→改中景（手部占比降低减少崩坏概率）

§三-4 动作模糊（看不清动作）
诊断：动作复杂度过高或运镜过快
修正：
  a. 拆镜：复杂连招→拆为2-3镜（起手→碰撞→结果）
  b. 降速：运镜从"快速横摇"→"中速跟拍"
  c. 减少同镜动作数：1主运镜+1主动作/特效
  d. 加定格描述："动作清晰可辨，肢体轨迹明确"

§三-5 色彩漂移（颜色串/变色）
诊断：多角色色彩签名冲突或光影锁不完整
修正：
  a. 检查光影锁是否完整（时间/天气/光源方向/色温/光比）
  b. 角色色彩签名拉开差距（冷色vs暖色至少差2档色温）
  c. 加负面词："色彩混色, 服装变色, 色彩串味"
  d. 同场景各镜光影锁强制一致

§三-6 空间断裂/穿模
诊断：空间锚不完整或站位轴断裂
修正：
  a. 检查六层锁是否完整（空间锚/状态锁/道具锁/光影锁/声音锁/交接帧）
  b. 补充交接帧（拆分视频首镜必加末帧描述）
  c. 穿模：加"物理碰撞真实，无穿透"描述
  d. 查空间连续性控制库18项自检

§三-7 风格漂移
诊断：风格前缀不完整或与生成模型不匹配
修正：
  a. 检查风格前缀是否完整加载
  b. 查生成模型适配层，确认该模型的风格偏好词
  c. 加负面词："风格漂移, 卡通化, 赛博朋克化"（按实际情况）
  d. 负面词放全局区块（模板C）或每镜追加（模板B/D）

§三-8 表情失败（太僵/面瘫）
诊断：表情描述过于笼统或情绪强度不匹配
修正：
  a. 查情绪弧线，确认该镜情绪强度%
  b. 补充微表情五要素：眉梢位移/咬肌/瞳孔/眨眼周期/指尖张力
  c. 高情绪峰值→查表情大全SECTION:B（4-5级）
  d. 表情与景别匹配：特写→微表情细节 / 中景→肢体情绪

§三-9 未分类（用户说不清）
处理：
  a. 列出10类失败模式让用户选
  b. 询问"能否截图？" → 参考生成检查与规避库.txt SECTION:B 封面图
  c. 尝试通用修正：加负面词+降低复杂度+检查锁定标签

四、项目级经验积累
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 触发时机：
每轮反馈完成后（无论成功失败），自动更新项目经验。

■ 经验类型：

1. 模型特征档案（per-model）
   记录该模型在本项目中的表现特征：
   - 已知弱项：如"LibTV手部动作复杂度>2级必崩"
   - 已知强项：如"Veo光影渲染优秀"
   - 字数甜区：如"可灵300-400字效果最佳"
   - 人群上限：如"Runway同镜清晰人物≤2"

2. 项目高频问题（per-project）
   统计本项目反复出现的问题：
   - 失败频次TOP3类型
   - 哪些镜号反复翻车
   - 哪些修正策略最有效

3. 预防性加固（feed-forward）
   基于项目经验，在下一集分镜生成时预防性加固：
   - 该模型手部弱→所有手部特写预设降级方案
   - 该项目仙侠题材→所有特效预设面部安全区保险词
   - 该模型字数甜区→自动调整字数预算

■ 经验文件：scripts/generation_log.json

格式：
{
  "project": "项目名",
  "model": "模型名",
  "model_profile": {
    "weaknesses": ["手部动作>2级必崩", "3+人群像必崩"],
    "strengths": ["光影渲染优秀", "微表情自然"],
    "sweet_spot_tokens": "500-800",
    "max_clear_characters": 2
  },
  "shot_history": {
    "镜1": {"attempts": 1, "result": "SUCCESS", "fixes": []},
    "镜4": {
      "attempts": 3,
      "result": "SUCCESS",
      "fixes": [
        {"attempt": 1, "failure": "面部崩坏", "fix": "第三人降层虚化"},
        {"attempt": 2, "failure": "手部失败", "fix": "结印降级为并指前点"},
        {"attempt": 3, "result": "SUCCESS", "note": "上述两修正有效"}
      ]
    }
  },
  "project_patterns": [
    "本模型手部弱→所有手部特写预设降级方案",
    "仙侠特效需加面部保险词"
  ],
  "stats": {
    "total_shots": 12,
    "success_first_try": 7,
    "needed_fix": 4,
    "abandoned": 1,
    "top_failures": [
      {"type": "手部失败", "count": 3},
      {"type": "面部崩坏", "count": 2}
    ]
  }
}

■ 经验更新时机：
1. 每次用户反馈后 → 更新shot_history + stats
2. 同一失败类型出现2次 → 写入model_profile.weaknesses
3. 同一修正策略有效2次 → 写入project_patterns
4. 新一集开始时 → 读取model_profile → 预防性加固

五、反馈闭环完整流程
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 流程图：

  分镜交付（步骤9完成）
      ↓
  用户生成视频
      ↓
  用户回来反馈结果 ──→ 无问题 ──→ 记录SUCCESS → 更新经验 → 结束
      ↓
  有问题镜号
      ↓
  自动归类失败类型（第二节关键词表）
      ↓
  生成修正建议（第三节修正策略）
      ↓
  展示给用户：镜X诊断+修正方案+修正后提示词差异
      ↓
  用户确认修正 ──→ 更新分镜 → 更新shots_locked.json（镜X降为MODIFIED）
      ↓
  用户重新生成该镜
      ↓
  回到"用户反馈结果" ←──┘（直到全部SUCCESS）

■ 与现有步骤的对接：

- 步骤9交付后 → 激活反馈闭环监听
- 反馈触发 → 不需要重新走步骤1-9，只需修正目标镜
- 修正范围 → 查shots_locked.json的dependency_chains确定影响范围
- 修正后 → 目标镜+影响范围镜重跑步骤8检查
- 通过后 → 重新标记LOCKED → 更新缓存

六、用户交互示例
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 示例1：单镜失败

用户："生成完了，镜1到镜5都行，镜6脸崩了"

skill内部处理：
1. 解析：镜1-5=SUCCESS，镜6=FAILED
2. 匹配关键词："脸崩" → 面部崩坏 → 规避库一.1
3. 检查镜6：几人？→ 4人清晰 → 超3人配额
4. 生成修正建议：
   "镜6诊断：4人清晰同框 → 面部崩坏（模型配额不足）
    修正方案：
    a. 第3-4人降层：宾客虚化70%+剪影
    b. 加负面词：多人物, 面部混淆
    c. 或拆镜：4人→2人+2人反应镜交替
    需要哪种？"
5. 用户选a → 修改镜6提示词 → 镜6降为MODIFIED → 重跑步骤8
6. 更新generation_log.json

■ 示例2：全部成功

用户："全部生成了，没问题"

skill内部处理：
1. 全镜标记SUCCESS
2. 更新generation_log.json（success_first_try +N）
3. 检查是否有新的model_profile强项发现
4. 简短回复："完美。已记录生成结果，本项目的模型表现良好。"

■ 示例3：反复失败

用户："镜8重roll了4次，每次手都不对"

skill内部处理：
1. 镜8第4次失败 → 手部失败
2. 查shot_history：镜8已修正3次仍失败
3. 触发升级策略：
   a. 手部动作直接降至最低安全档（藏手/握拳）
   b. 建议改中景（手部占比降低）
   c. 建议换模型（查model_profile弱项）
4. "镜8手部已重试4次，建议：
    a. 手部动作改为'右手握拳垂于体侧'（最低安全档）
    b. 或从特写改为中景（降低手部画面占比）
    c. 或换用Veo/Sora（手部渲染更强）
    选哪个？"
5. 更新model_profile.weaknesses："手部动作反复失败"
