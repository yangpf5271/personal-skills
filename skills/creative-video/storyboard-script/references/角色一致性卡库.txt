【为什么需要角色卡】
角色锚定串每镜复写50+字 → 30段就是1500+字的纯重复外貌描述。
角色卡把不变的外貌信息定义一次，全局引用，释放逐镜字数空间给动作和情绪描述。
同时提供比锚定串更完整的角色档案，减少跨镜/跨集的角色漂移。

核心设计原则：
- 不变的全局化（角色外貌/基础站位/场景光影/环境音 → 全局块一次输出）
- 变的才逐镜写（角色移动/道具变化/情绪转折/动作 → 逐镜写差异项）

角色卡标准格式
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 标准格式

[角色卡]
代号：xxx（不用IP真名，用代称——配合版权词处理指南）
性别：男/女
年龄感：xx岁视觉年龄

外貌锚定：
  脸型：xxx（长方脸/鹅蛋脸/圆脸/菱形脸/心形脸/国字脸）
  五官：眉xxx/眼xxx/鼻xxx/唇xxx/耳xxx
  肤色：xxx（偏白有血色/小麦色/冷白皮/暖黄皮）
  发型发色：xxx（颜色+长度+造型+质感）
  体型：xxx（高瘦精壮/魁梧壮实/纤细柔美/比例cm感）
  特征标记：xxx（疤痕/刺青/胎记/瞳纹变化/无）

服装变体：
  默认：xxx（完整描述：主要服装+配件+鞋靴+色彩占比）
  变体A（如有）：xxx（换装/变身/受伤后）

色彩签名：主色(#XXXXXX) XX% + 辅色(#XXXXXX) XX% + 点缀色(#XXXXXX) XX%
典型表情库：表情1 / 表情2 / 表情3 / 表情4 / 表情5 / 表情6
声线方向（TTS/配音参考）：xxx（音色/语速/尾音习惯）

■ 写法规则
- 代号用"颜色+装备/特征"格式（如"赤甲武者"），不用真名
- 外貌锚定精确到可以用一张参考图锁定的程度
- 色彩签名用HEX色值+占比，不要写"红色为主"这种模糊描述
- 典型表情库存放该角色最常出现的5-8个表情，供步骤5表情规划时匹配
- 声线方向是参考项，不强制输出（用户有配音需求时才写）
- 角色卡构建后，如有参考图，标注"【参考图N】"供图生视频模式引用

■ 与角色锚定串的关系
角色锚定串（空间连续性控制库中定义）：
  姓名+确切年龄+身份+发型发色+瞳色+服装关键词+配色
  → 简版，每镜复写用

角色卡（本库定义）：
  代号+性别+年龄感+外貌锚定(6维)+服装变体+色彩签名+表情库+声线
  → 完整版，全局定义一次用

角色卡 = 角色锚定串的超集。锚定串是角色卡的精简提取版。

══════════ SECTION:B-输出模式 ══════════
全局模式 vs 逐镜模式
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

这是本库的核心设计——根据模板选择锁定信息的输出方式：

■ 全局模式（模板A/B/D）

适用场景：单次输出3-40段分镜时，避免逐镜重复锁定标签造成token爆炸。

输出位置：全局前缀块（分镜正文之前），全剧只输出一次。

全局前缀块结构：
┌─────────────────────────────────────────────────────┐
│ [全局锁定块]                                        │
│ [角色卡]角色A=代号+外貌锚定+服装+色彩签名          │
│         角色B=代号+外貌锚定+服装+色彩签名          │
│ [空间锚]场景名，家具位置，门窗方位，角色固定位置    │
│ [状态锁]角色A=姿态/位置，角色B=姿态/位置           │
│ [道具锁]角色A=道具/着装，角色B=道具/着装           │
│ [光影锁]时间/天气/光源方向/色温/光比               │
│ [声音锁]环境底噪+持续音源                           │
│ [全局防崩锁词(可选)]                               │
└─────────────────────────────────────────────────────┘
→ 后接画质风格前缀 → 各分镜正文

逐镜规则（全局模式下）：
- 不再每镜复写[空间锚][状态锁][道具锁][光影锁][声音锁][角色锚定串]
- 仅在该镜发生状态变化时，在画面描述或备注中写明变化：
  · 角色移动 → "角色A从画面左侧移至画面中央"
  · 道具变化 → "角色A放下茶杯，空手"
  · 换装/受伤 → "角色A前襟被泼湿"（后续镜自动延续，不再标注）
  · 场景切换 → 新场景写一组新的[空间锚][光影锁][声音锁]放该段开头
  · 跨视频拆分 → 拆分后新视频首镜写[交接]标签+当前状态摘要
- 无变化时，该镜直接从画质风格开始，不写任何锁定标签

■ 逐镜模式（模板C）

适用场景：S级制作交付，每镜需要完整独立信息，可单独提交生成。

输出位置：每镜的对应字段中完整展开。

每镜结构：
[角色锚定串] + [空间锚] + [状态锁] + [道具锁] + [光影锁] + [声音锁]
→ 画质风格 → 镜头 → 构图 → 画面描述 → ...

规则（与现有空间连续性控制库完全一致）：
- 每镜强制复写全部六层锁定标签，即使无变化
- 角色锚定串从角色卡中提取，每镜展开
- 18项空间连续性自检清单逐镜过

■ 模式选择规则
| 模板 | 模式 | 锁定信息输出位置 | 复写策略 |
|------|------|-----------------|----------|
| A | 全局 | 全局前缀块一次 | 仅写变化项 |
| B | 全局 | 全局前缀块一次 | 仅写变化项 |
| C | 逐镜 | 每镜独立展开 | 强制全量复写 |
| D | 全局 | 全局前缀块一次 | 仅写变化项 |

■ 多场景处理（全局模式下）
当分镜涉及多个场景时：
- 每个场景在首次出现时，写一组该场景的[空间锚][光影锁][声音锁]
- 放在该场景第一个分镜的标题行之后、正文之前
- 后续同场景分镜不再复写，除非场景内布局发生变化
- 切回已出现过的场景时，标注"场景：xxx（锁定信息见前）"

■ 快速模式处理
快速模式（Q1→Q2→Q3）默认使用模板D → 全局模式。
全局锁定块在Q3输出时放在分镜正文之前，一次输出。
不与用户讨论锁定块内容——内部构建，直接输出。

══════════ SECTION:C-锁定体系整合 ══════════
与六层锁定体系的关系
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

角色卡不是独立系统，是对现有六层锁定体系的升级层。

■ 整合前（当前状态）
每镜输出：
  [角色锚定串]50字 + [空间锚]30字 + [状态锁]40字 + [道具锁]40字 +
  [光影锁]20字 + [声音锁]20字 = ~200字纯锁定标签/镜
30段分镜 = 6000字纯重复锁定信息

■ 整合后（全局模式）
全局前缀块输出一次：
  [角色卡]×N + [空间锚] + [状态锁] + [道具锁] + [光影锁] + [声音锁]
  = ~300-500字（取决于角色数量）
30段分镜 = 300-500字全局 + 各镜变化项（平均每镜10-30字）
= 总计约1000-1500字，节省75%+

逐镜模式（模板C）不节省，但每镜信息更完整。

■ 六层锁定标签在全局模式下的变化

| 锁定层 | 全局模式 | 逐镜模式(C) |
|--------|----------|-------------|
| 角色锚定串 | →升级为角色卡，全局输出一次 | 保持每镜复写 |
| L1空间锚 | 全局输出一次/场景 | 每镜复写 |
| L2状态锁 | 全局输出基础状态，逐镜仅写变化 | 每镜复写全部 |
| L3道具锁 | 全局输出基础状态，逐镜仅写变化 | 每镜复写全部 |
| L4交接帧 | 跨视频拆分时写（不变） | 同左 |
| L5光影锁 | 全局输出一次/场景 | 每镜复写 |
| L6声音锁 | 全局输出一次/场景 | 每镜复写 |

■ 自检清单适配

全局模式下，自检清单调整：
- 原18项逐镜检查 → 改为"全局块完整性检查"+"逐镜变化项检查"
- 全局块检查：角色卡/空间锚/光影锁/声音锁是否完整且只输出一次
- 逐镜检查：有变化时是否标注了变化？无变化时是否省略了锁定标签（而非重复）？
- 模板C不变，仍用原18项逐镜检查

■ 跨集复用规则
- 多集系列：步骤1.8加载上集 characters.json → 新增角色追加 → 修改角色更新
- 跨集角色一致性：角色卡定义后，全系列所有集共用同一张卡
- 角色弧光推进（如换装/受伤/觉醒）在卡的"costumes.variants"中追加，不覆盖默认
- 上集末帧物理状态（受伤/破损）从 episode_snapshot.json 继承，写入下集首镜备注

■ 角色卡构建时机

在步骤1（确认输入范围、风格和时长）之后、步骤2（拆节奏画弧线）之前：

1. 扫描用户剧情文本，提取所有出场角色
2. 为每个角色构建角色卡（参照SECTION:A格式）
3. 检查 scripts/characters.json 是否已存在（多集系列/已有项目）
   - 已存在 → 加载已有角色卡 → 与新角色合并 → 标注新增/修改
   - 不存在 → 创建新文件
4. 如果是IP改编，配合 references/版权词处理指南.txt 进行代号化
5. 如果用户提供了参考图，标注【参考图N】关联角色
6. 角色卡构建完成后：
   - 全局模式(A/B/D) → 放入全局前缀块
   - 逐镜模式(C) → 作为源数据供每镜提取锚定串
