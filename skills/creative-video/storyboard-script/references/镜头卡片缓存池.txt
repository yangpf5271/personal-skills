镜头卡片缓存池
references/镜头卡片缓存池.txt ｜ V1.0
════════════════════════════════════════════════════════════

【概述】
缓存池解决两个核心问题：
1. 用户修改单镜时全表重跑的浪费 → 增量修改策略
2. 多集系列下集无法继承上集状态 → 跨集状态快照

缓存文件存放在 scripts/ 目录下（由SKILL在执行过程中自动创建和更新）。

一、缓存文件结构
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ shots_locked.json（单集锁定状态）

格式：
{
  "episode": "第1集",
  "total_shots": 35,
  "last_modified": "ISO时间戳",
  "shots": {
    "镜号": {
      "status": "LOCKED | PENDING | MODIFIED",
      "locked_at": "ISO时间戳",
      "checks_passed": ["可行性", "失败规避", "空间连续性", "转场", "钩卡质检", "音效"],
      "downstream_dependency": ["下游依赖镜号列表"]
    }
  },
  "dependency_chains": {
    "表情修改":   ["目标镜", "+1下游镜（视线匹配检查）"],
    "站位修改":   ["目标镜", "同场景所有后续镜（空间锚重算+站位轴坐标更新）"],
    "道具修改":   ["目标镜", "后续所有镜直到道具状态变化（道具锁延续）"],
    "台词修改":   ["目标镜", "+1下游镜（口型/情绪衔接检查）"],
    "运镜修改":   ["目标镜仅本镜"],
    "场景修改":   ["该场景所有镜（空间锚+光影锁+声音锁+场景锚点全部重算）"],
    "增删镜":     ["插入点之后所有镜（重新编号+空间锚/站位轴/道具锁链全部重算）"]
  }
}

状态说明：
- LOCKED：已通过步骤8六项检查且用户确认通过，后续修改不触发重跑
- PENDING：新生成或刚修改完、尚未通过步骤8检查
- MODIFIED：原本LOCKED，因上游镜修改导致本条依赖被打破，降为MODIFIED待重检

■ episode_snapshot.json（跨集状态快照，多集系列用）

格式：
{
  "series": "系列名称",
  "episodes": {
    "第1集": {
      "final_shot_id": 35,
      "snapshot": {
        "scene": "分→",
        "characters": [
          {
            "name": "角色名",
            "position": "站产床右侧",
            "pose": "站立、双手叉腰",
            "expression": "眉头紧锁、眼神凝重",
            "props": "空手、绿衣完好",
            "physical_state": "衣物完好（无受伤/无泼溅）"
          }
        ],
        "lighting": "无影灯白光",
        "time": "日间",
        "atmosphere": "紧张凝重"
      }
    }
  }
}

下集生成时自动加载上集 episode_snapshot.json，作为初始空间的锚定基准。
末帧所有角色位置/姿态/道具/着装/受伤等物理状态，直接写入下集第一镜的空间锚+状态锁+道具锁。

二、增量修改策略（修改单镜触发逻辑）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

核心原则：只动该动的，LOCKED镜不动。

■ 修改分类与影响范围：

| 修改类型 | 影响范围 | 重跑步骤 |
|---------|---------|---------|
| 改表情（单个角色） | 目标镜 + 下游1镜（视线匹配） | 步骤5→步骤8 |
| 改站位姿势（单个角色） | 目标镜 + 同场景后续所有镜（空间锚/站位轴重算） | 步骤3.5→步骤4→步骤8 |
| 改道具/着装 | 目标镜 + 后续所有镜直到道具变化（道具锁链重算） | 步骤3.5→步骤8 |
| 改台词 | 目标镜 + 下游1镜（口型/情绪衔接） | 步骤5→步骤8 |
| 改运镜 | 仅目标镜 | 步骤6→步骤8 |
| 改场景设定 | 该场景所有镜（空间锚+光影锁+声音锁+场景锚点全重算） | 步骤3.5→步骤4→步骤8 |
| 增删镜头 | 插入点之后所有镜（重新编号+依赖链全重算） | 步骤2→3.5→4→5→6→7→8 |
| 换模板 | 全部镜头（整版重排） | 步骤7全量重跑 |

■ 执行流程：

1. 读取 shots_locked.json
2. 定位修改目标镜号 N
3. 查 dependency_chains 确定影响范围
4. 影响范围内的非LOCKED镜 → 解除为PENDING → 重跑对应步骤
5. LOCKED镜在影响范围外 → 跳过，直接复用
6. 影响范围内的原本LOCKED镜 → 降为MODIFIED → 重跑步骤8自检
7. 全部通过后 → 本次修改涉及镜重新标记为LOCKED → 更新缓存

■ 状态流转图：

  [新生成] → PENDING → 步骤8通过 → LOCKED
                                            ↓ (上游修改触发)
                                       MODIFIED → 步骤8重检 → LOCKED

三、跨集状态快照机制
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 触发时机：
- 完成一集全部分镜并用户确认后，自动生成 episode_snapshot.json
- 下集分镜生成时，先检查是否存在上集快照

■ 继承规则：
1. 场景继承：上集末帧场景 → 下集第一镜场景锚点初始值
2. 角色位置继承：上集末帧角色位置 → 下集第一镜空间锚+站位轴的初始坐标
3. 道具着装继承：上集末帧道具状态 → 下集第一镜道具锁初始值（含受伤/泼溅等物理状态延续）
4. 时间继承：上集末帧时间 → 下集第一镜时间基准（可自然推进）
5. 光影继承：上集末帧光影 → 下集第一镜光影锁初始值

■ 铁律：
- 末帧角色如果有物理状态变化（受伤/衣物破损/被泼等），继承时原样带入，禁止"自动恢复"
- 除非剧情明确写了"换装"或"恢复"，否则物理状态跨集不重置

■ 示例模板（下集第一镜的空间锚初始块）：

[空间锚]继承自第X集末帧——
  场景：XX，XX道具居中，XX角色站XX位置
[状态锁]继承自第X集末帧——
  XX角色=站立/XX位置/XX姿态
[道具锁]继承自第X集末帧——
  XX角色=右手持XX/外套破损（第X集战斗后状态延续）/XX完好


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
四、与步骤8自检闸的配合
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 全量生成流程（无缓存时）：
  步骤8 → 六项全检 → 全部通过 → 全部标记LOCKED → 写入缓存

■ 增量修改流程（有缓存时）：
  LOCKED镜（影响范围外）→ 跳过步骤8，直接复用
  MODIFIED/PENDING镜（影响范围内）→ 走步骤8全检 → 通过后标记LOCKED

■ 缓存失效条件（强制全量重跑步骤8）：
  - 增删镜头（依赖链完全打乱）
  - 场景修改（空间锚/光影/声音全部重置）
  - 换模板（生成模型变更）
  - 跨集切换（新一集，上集LOCKED仅用于快照继承，不用于检查跳过）
