### P2. Token 预算跟踪

执行中累计已加载文件 token 估算。每步加载文件后，调用 scripts/token_tracker.py 的 `RuntimeTokenTracker.track(filepath, step)` 记录文件名+大小+步骤。累计达阈值70%时预警(warn)，达85%时危险(critical)，输出释放建议（列出已完成步骤可释放的大文件）。
- 估算公式：tokens ≈ 文件字节数 × 0.4
- 默认阈值：128K（128K模型）/ 200K（Claude等大窗口模型）
- 预警时策略：优先释放已完成步骤的大文件引用，后续步骤用索引定位替代全文加载
- 会话记录持久化到 scripts/token_session.json，可事后分析
- 段落加载限制联动：token<80K时可加载≤3段落，≥80K退回≤2段落

### P3. 兜底规则

题材路由表或专属库缺失/不可读时：
- 降级：只用通用库，运镜用基础模板（推/拉/摇/移），动作用基础肢体描述，特效写"无"
- 提示用户部分库不可用，建议稍后重试
- 路由表缺失时跳过题材路由，仅用通用库推进

### P4. 模型世代适配

生成模型按原生单次生成时长分两级，**仅影响模板D/E**的镜头推算、单镜时长上限、一镜多节合并策略。模板A/B/C固定标准级（≤15秒）：

| 级别 | 标准 | 代表模型 | 单镜时长上限 | 30秒视频镜头数 | 一镜多节上限 |
|------|------|---------|------------|--------------|------------|
| 标准 | 原生≤15秒 | Kling 1.5/2.0、即梦(Seedance 2.0)、Runway Gen-3、LibTV、Sora | ≤15秒 | 4-8镜 | 3-5节（打斗6-8） |
| 长生成 | 原生≥30秒 | Seedance 2.5+、Veo 3+ | ≤30秒 | 2-4镜 | 5-8节（打斗8-12） |

- 用户指定模型→模板D/E按对应级别套用参数；模板A/B/C固定标准级不受影响
- 未指定模型→默认标准级，步骤7f询问用户时一并确认模型级别（仅模板D/E生效）
- 混合使用（部分镜用长生成、部分用标准）→仅模板D/E逐镜标注模型，按镜套级别
- 长生成级额外能力适配（仅模板D/E）：①50路多模态参考→角色一致性卡优先转为参考图输入而非纯文字锚定 ②局部编辑→步骤10反馈闭环优先用局部编辑指令而非整镜重生成 ③30秒原生直出→同场景多节拍合为一镜，减少接缝

## 使用引导：首次使用或模糊请求

满足任一条件时先三问快筛：首次使用 / 请求模糊（无题材风格时长）/ 用户说"测试""试试"。

**三问**（一次性问出）：① 题材方向？② 主感觉是什么？是否叠加 1-2 个次感觉？③ 视频多长？
收到后自动路由+风格推荐+时长推算，直接进入快速模式Q1。

默认值：题材未指定→现代都市，主感觉未指定→剧情感，次感觉未指定→空，时长未指定→按文本长度推断（1分钟≈3-5镜）。
已含明确题材+风格+时长 → 跳过三问，直接进入模式选择。

## 模式选择

**快速模式（3步）**：用户说"测试/快速/草稿" / ≤30秒 / 单场景 / 已有剧情文本 / 未指定多集S级
**完整模式（10步）**：用户说"正式/S级/完整交付" / 多集 / 复杂多场景 / 要求详细确认
**默认**：模糊→快速模式。快速模式中用户要求多集或S级→切换完整模式从步骤1开始。

**快速模式保障差异说明**（用户问起时告知）：快速模式跳过以下保障——角色一致性卡(步骤1.8) / IP版权词检测 / 拍摄风格叠加 / 感性意图冲突检测 / 缓存池增量模式 / 跨集快照。基础保障仍保留：六层空间锁 / 视觉分层 / 表情弧线 / 运镜动作 / 钩子卡点 / 75项质量检查 / 转场标注。如需角色一致性或版权词处理，请用完整模式。

## 快速模式（3步）

### Q1：自动路由

不问问题，从文本推断一切。
1. **题材路由**：Read 题材路由表确定题材簇（A-G），记录专属库清单。不询问确认。
2. **自动选风格**：按题材簇选默认视觉风格（簇A=3D写实市井 / B=都市电影 / C=仙侠水墨 / D=武侠电影 / E=奇幻史诗 / F=悬疑暗调 / G=明亮轻松）。用户有偏好优先用。**画风检测**：扫描用户输入关键词（番剧/动漫/anime/二次元/sakuga/日漫/国漫/2D/赛璐珞/作画），命中→标记`画风=番剧`，后续武戏场景时2.4.5弹药库触发器据此激活。
3. **调出风格前缀**：P1检索知识库-视频风格.txt SECTION:H（风格前缀速查，7模板全文）。
4. **推算镜头数**：Read 根据剧情故事转脚本.txt 的节奏规则。未给时长则按文本长度推断。
5. **跳过**：平台/受众/语气/约束——默认值（通用短视频/剧情感/9:16）。

**Q1.5 感性意图解码**：先识别用户是否显式给出`主感觉/次感觉`。若给出，则主感觉作为主轴，次感觉最多保留2个；若未给出，则从文本扫描感性关键词自动推断。Read 感性意图解码表索引→仅加载命中意图块→提取7项参数偏移{运镜倾向,特效密度,节奏系数,景别分布,构图倾向,光影倾向,音效策略}。合并规则改为：**主感觉定基调，次感觉做辅助偏移**；快速模式按权重合并（主感觉约70%，两个次感觉各约15%）。若次感觉与主感觉明显冲突，快速模式不暂停，直接保留主感觉并丢弃冲突次感觉。参数偏好摘要内部记录，流入Q2各步骤。详见完整模式步骤1.5。

### Q2：自动锁定（一步到位）

1. **拆节奏**：按叙事结构拆钩子/展开/重点/收束。一镜多节合并（同场景+同人物+连贯动作→一镜含3-5节）。单镜≤15秒。**场景类型判定**：每个场景段按步骤2.4.4判定文戏/武戏/混合，决定后续步骤走2.4.5或2.4.6。
2. **情绪弧线**：从文本推断角色情绪轨迹，作为表情硬约束。内部使用不输出。
3. **AIGC通用参数**：加载 AIGC-真人短剧-漫剧通用提示词.txt 作全局基准。
4. **六层空间锁**：按 P1 索引协议检索空间连续性控制库 L1~L7。L7双模式：全局模式(A/B/D)放前缀块输出一次，逐镜模式(C)每镜复写。场景模板：Read 场景参考库选取对应场景，5维参数转化为空间锚/光影锁/声音锁。
5. **视觉参数**：Read S级视觉分层库.txt（16KB全文加载）。台词选词按 P1 检索词汇库。跨镜头转场按 P1 检索转场系统参数库.txt（SECTION:F决策树选型→SECTION:G查模型兼容性→SECTION:H失败规避）。转场标注挂在运镜字段末尾，格式 `| 转场：类型[时长]（原因）`，第一镜不标注。
6. **表情**：匹配情绪弧线。常规读知识库-表情大全.txt SECTION:A；高情绪峰值按 P1 检索知识库-表情大全.txt SECTION:B。**文戏场景**→按步骤2.4.6④⑤⑥⑫执行。
7. **运镜/动作/特效**：按题材路由结果加载专属库。遵循 P1 索引协议和 P3 兜底规则。**文戏场景**→按步骤2.4.6⑧⑨⑩执行。文戏运镜池：过肩正反打/缓慢推近/锁定平移/微距手持/焦点转移/升降展开。
8. **钩子设计**：按 P1 检索节奏与钩子设计库.txt SECTION:A，时间锚点内联应用（3秒钩/7秒反转/15秒爆点/30秒留坑），按时长缩放。同时内联SECTION:B爽点节奏的密度与反转参数。

### Q3：直接输出

1. **输出模板D**（快速模式缺省）：即梦提示词直出格式。用户说"一镜到底"用模板A，说"多镜快切"用模板B。快速模式不用模板C。
2. **字数预算**：每条提示词≤350中文字符。用户指定模型时按生成模型适配层调整。
3. **内部检查**（静默执行）：12条可行性+10项否决 / 失败规避扫雷 / 18项空间连续性自检 / 转场6项检查（类型匹配/参数标注/前后衔接/空间连续性/模型兼容/铁律合规）+转场标注格式检查（运镜末尾`|转场：`格式/第一镜不标注/特效转场≤3次）/ 钩卡质检9条 / 音效合规 / 文戏专检（同步骤8⑦，9项）/ 武戏专检（同步骤8⑥b，禁用词扫描+回合结构+命中四段+空间推进）。不通过→修正后再输出。
4. **输出分镜**：逐镜卡片。**只输出分镜本身**——不附设计说明、不附自检表、不附验证清单、不附设计思路、不附对比分析、不附任何元内容。检查全部静默执行，不通过就修正后再输出，用户只看到最终成品。
5. **输出后提问**：仅在用户未指定模型时问"使用哪个生成模型？"——快速模式唯一会问的问题。
6. **迭代**：同完整模式步骤9规则。用户要求多集/S级/复杂修改→切换完整模式。

**升级触发**：用户要求多集规划 / 模板C / 详细确认 / 明确说"完整模式"。

## 完整模式（10步）

### 步骤 1：确认输入范围、风格和时长 `[1/9]`

1. **视觉风格**：按 P1 检索知识库-视频风格.txt 引导用户选择→确认风格前不展开分镜→P1检索知识库-视频风格.txt SECTION:H 获取风格前缀。**画风检测**：扫描用户输入关键词（番剧/动漫/anime/二次元/sakuga/日漫/国漫/2D/赛璐珞/作画），命中→标记`画风=番剧`，后续武戏场景时2.4.5弹药库触发器据此激活。
2. **拍摄风格（可选·默认隐藏）**：画风确认后简短追问"是否需要叠加特定拍摄风格？"用户**是**→加载拍摄风格.txt（19种，正向串拼入前缀/反向串填入Negative）；**否或不回应**→跳过不加载。快速模式跳过。  
   - 对话引导中，拍摄风格优先按**常规热门度**给出：王家卫 / 诺兰 / 维伦纽瓦 / 赛博朋克 / 纪录片写实 / 港风复古 / 是枝裕和 / 黑色Noir / 希区柯克 / 朴赞郁 / 黑泽明 / 奉俊昊 / 林奇 / 韦斯安德森 / 雷德利·斯科特 / 昆汀 / VHS家庭录像 / 俄式阴郁 / 塔蒂。
   - 若用户明确给出**自定义拍摄风格**，先在拍摄风格.txt 中做就近匹配；若没有完全对应项，则把用户描述拆成`色调/光影/质感/构图/机位倾向`五项，作为自定义拍摄风格偏移叠加到现有画风前缀上，而不是忽略。
   - 拍摄风格是**影像语言叠加层**，不替代题材路由和画风主簇。优先保证题材、画风、主感觉成立，再用拍摄风格做调味；若明显冲突，以题材和主感觉为先。
3. **题材路由**：Read 题材路由表确定题材簇(A-G)，记录步骤6专属库清单。混合题材按跨簇组合规则（主簇必选+副簇按需）。
4. **时长确认**：参考根据剧情故事转脚本.txt 推算镜头数/段落占比/反转高潮/结尾留坑。
5. **多集系列**：确认总集数/本次写哪集/单集时长→调用多集系列规划库.txt→输出立项规划表给用户确认→确认后进入单集分镜。单集跳过。
6. **补全信息**：平台/目标/受众/语气/约束。缺少不可逆细节时提最小问题组。

### 步骤 1.5：感性意图解码

1. 先识别用户是否显式给出`主感觉`与`次感觉`。推荐结构为：**1个主感觉 + 0~2个次感觉**。若用户给出超过2个次感觉，只保留最明确的前2个，其余忽略。
2. 若用户未显式给出，则扫描消息中的感性关键词（如"特效拉满""燃""压抑""唯美"等），自动推断1个主感觉，并从剩余高频信号中补出最多2个次感觉。
3. 按 P1 检索感性意图解码表，仅加载命中意图块（7项参数偏移）。
4. **合并规则**：主感觉负责整体基调、镜头第一优先级和爽点方向；次感觉只做辅助偏移，不得反客为主。完整模式默认按加权叠加处理（主感觉约70%，两个次感觉各约15%；若只有1个次感觉，则约30%）。
5. **冲突处理**：若次感觉与主感觉明显冲突（如高燃爽感+克制留白、轻松解压+压迫窒息、甜宠拉扯+黑化复仇），暂停给用户二选一：`保留主感觉并删除冲突次感觉` 或 `改主感觉`。若无冲突直接叠加。
6. **参数偏好摘要**注入后续所有步骤：步骤2弧线受节奏系数约束→步骤4视觉按景别/光影偏移→步骤5表情按倾向选型→步骤6运镜/特效按倾向匹配SECTION→步骤7.5特效密度提高时预警字数→步骤8钩子/爽点按节奏系数缩放。
7. 感性解码是**加权偏移**非硬覆盖——文戏转场镜头仍需干净，只提高关键帧倾向权重；主感觉持续生效，次感觉只在对应段落、峰值镜或情绪强化镜头上增加权重。

1. **节奏拆分**：钩子（前3秒抓注意力）→ 核心展开 → 重点强化 → 收束结尾。
2. **钩子卡点设计**：按 P1 检索节奏与钩子设计库.txt SECTION:A。四档卡点（3秒钩/7秒反转/15秒爆点/30秒留坑）按集长换算。6型开场钩选1-2型，首帧有反常物，主角脸3秒内出现。集尾留钩按公式1-4设计。多集维护钩子台账。

4. **一镜多节**：同场景+同人物+连贯动作→合并为一镜（3-5节，打斗可6-8节；模板A/B/C单镜≤15秒，模板D单镜按 P4 分级）。切镜条件：场景切换/时间跳跃/情绪180°翻转/人物全换。用户要求"不切镜"→匹配INTENT:13+模板A。
4.4. **场景类型判定**（文戏/武戏/混合）：一镜多节拆分后，对每个场景段判定类型，决定激活2.4.5（武戏）或2.4.6（文戏）或两者。三维度按优先级判定：

  | 维度 | 武戏信号 | 文戏信号 |
  |------|---------|---------|
  | ① 主体动作（角色主要在做什么） | 拳/脚/兵器/法术/异能对攻，物理冲突是场景主体 | 说/看/等/走/坐/转身/递物/沉默/拥抱，情绪表达是场景主体 |
  | ② 叙事功能（场景在剧情里干什么） | 展示实力差距/制造危机/转折高潮/角色爆发/胜负结算 | 建立关系/揭示信息/情绪转变/铺垫伏笔/关系破裂或修复 |
  | ③ 画面主体（镜头最抓眼球的是什么） | 身体碰撞/武器交锋/特效爆发/速度冲击/破坏痕迹 | 面部表情/眼神交流/肢体微动/道具交互/空间距离变化 |

  - 信号词速查——武戏：打/斗/格/杀/战/搏/击/劈/刺/拳/脚/刀/剑/枪/挡/踢/摔/爆/冲/撞/飞；文戏：说/哭/笑/怒/惊/望/等/转身/离开/沉默/犹豫/拥抱/握手/递/接/放/叹/颤抖/咬唇
  - **混合场景处理**：
    - 打斗中插台词（对打时喊话）→ 判武戏，台词挂在打斗节奏内，不触发文戏对白协议
    - 文戏中单次肢体冲突（推搡/扇耳光/摔杯子）→ 判文戏，肢体冲突作为情绪触发器（按2.4.6③触发器规则处理）
    - 文戏转武戏（谈判破裂开打）→ 拆两段，前段文戏走2.4.6，后段武戏走2.4.5，拆点=首次持续物理对抗
    - 武戏转文戏（打完对话）→ 拆两段，拆点=物理对抗结束后的首个静止帧
  - **默认规则**：三维度矛盾时以①主体动作为准（占时长最长的动作类型）；同场景两种类型时长接近（4:6~6:4）→ 必须拆场景段

4.5. **打斗镜头节奏冲击法则**（强制·V3）：场景判定为武戏（按2.4.4）时执行。一律用模板B/D快切，**禁止模板A一镜到底**（一镜到底打斗=监控录像，无冲击力）。十三条硬规则：
  - ① **呼吸节奏+两种慢**：短镜快切（2-4秒）+长镜缓拍（5-8秒）交替，形成"紧-松-紧"波形，禁止均匀时长排列。节奏感来自幅度落差（小幅度慢拍↔大幅度爆发），非速度——"全程快=没有快"。两种慢必须分清：
    - A类·真升格（slow-motion）：受控放开——命中顿微升格（~0.3-0.5s、可多次）+名场面大升格（全片1次、≤0.4s），每次必绑流动元素（碎屑/火花/水花仍流）+ramp in→snap back
    - B类·低幅度慢拍（蓄力/接招/对峙/收势）：画面照常动（气场涨/发丝飘/肌肉绷/气纹内收），动作幅度极小——这是节奏感的主来源，每回合必有，照常计入节点
  - ② **硬切落撞击帧+动势衔接**：切镜时机必须在物理碰撞瞬间（拳着肉/刀格挡/冲击波扩散），每次硬切=一个视觉冲击点。切点必须遵守动势衔接四法则：弧线跟随（动作走完整弧线起势→发力→follow-through）、切在动作中段（cut on action，切点落在挥砍/突进中途，禁在静止帧切）、方向接力（match-cut，切前切后运动方向一致，残影与速度线指向落点）、收势变起势（上一招收尾直接长成下一招起手，动作像一条不断的线穿过切点）
  - ③ **峰值镜最短+禁停格**（★ V3关键修正）：全片最短镜（1.5-3秒）用于冲击峰值。**AI视频模型无帧级控制力，"定格/停格/顿帧/静默/画面冻结"会导致画面真停住**——冲击强调改用不停画面的手法：白闪一两帧（画面继续走）+镜头猛震一颤+命中点径向速度模糊+速度线爆开+色彩瞬间提亮。峰值镜的"窒息感"靠B类慢拍（蓄力/对峙、画面在动）做铺垫，靠爆发时的幅度+特效突变砸出重音，不靠冻结画面
  - ④ **运镜不重复+运镜升级**：每镜运镜必须不同，**全镜不重复**（非仅相邻两镜）。打斗场景运镜必须使用复合联动(B)/动态特效(C)/仙侠专项(D)级别运镜，禁止仅用基础单一运镜（推/拉/摇/移/环绕/升降）。同一基础动作（推/拉/环绕等）全镜最多出现1次。番剧/动漫风格→追加按 P1 检索番剧作画打斗弹药库.txt·疯切运镜库
  - ④b **运镜速度曲线**：每镜运镜必须自带速度变化（急刹/变速/突变/螺旋减速/静止→爆发等），禁止全程匀速。速度曲线变化本身即是节奏冲击的一部分
  - ⑤ **特写限量+特写标点**：特写每场最多1-2次，只给冲击峰值或转折帧；滥用特写=冲击力贬值。番剧风格→按 P1 检索番剧作画打斗弹药库.txt·特写标点库（握拳预告/蹬地力源/移动速度/眼神锁定/命中局部/被击反应，每个特写有专职）

  - ⑬ **无剧情必造剧**：用户未给剧情时，先设计4-6个因果事件微剧情（目标→转折→结果三幕），再让情绪链挂在剧情节拍上。转折必须从参考图独有视觉证据生长，禁止套用模板
5. **情绪弧线**：每角色每节奏段标情绪强度%。必须递进不跳跃。相邻镜波动≤40%（突遭暴击除外）。反派与主角弧线对称。弧线表先给用户确认，确认后作步骤5表情硬约束。

`[锁定标签] → [画质风格] → [镜头] → [构图] → [画面描述] → [光影] → [特效] → [台词] → [音效]`

- **模板E模版三动作连续性规则**：模版三必须优先保证“持续走位、切角绕后、侧闪反进、因果清楚、接触点清楚”。只有碰撞瞬间允许极短顿挫或微慢镜；禁止站桩轮流出招、无因果瞬移、长时间蓄力、动作糊成光团、无故换轴、360度乱绕、特效遮挡接触点。
- **模板E独立提示词包强规则**：当模板E按`单集总时长 ÷ 单个提示词总时长`输出多条提示词时，**每一条提示词都必须是一个可单独复制到 Seedance 的完整包**。  
  - 若使用`模版一/模版二`，则每条提示词都必须从段首开始依次包含：段首标题`【提示词N】【整集覆盖时间段】` + 本条专属锁定区 + 本条内部逐镜提示词 + 本条专属负面约束 + 分界线`--------------------------------------`
  - 若使用`模版三`，则每条提示词都必须完整包含：`【整体战斗设定】` + 本条`【分镜】` + 本条`【负面提示词】`；同样必须做到单条可独立复制，不得把整体战斗设定只写在第一条、后面几条省略
- **模板E分条时间双轨规则**：若使用`模版一/模版二`，则每条提示词的段首标题时间段用于标记它在整集叙事中的覆盖区间，但**该条提示词内部的镜头时间轴必须重新从`00:00`开始计算**。若使用`模版三`，则不强制段首标题，直接以该条内部的战斗分镜时间轴为准；同样禁止把上一条的尾时间直接续写到下一条内部。
- **模板E分条内容动态锁定规则**：若使用`模版一/模版二`，虽然每条提示词都必须重复完整的`<Asset_Setup>`、空间锁和负面约束，但这些内容**不能机械照抄成完全同一套文本**。若使用`模版三`，则每条的`【整体战斗设定】`也必须根据该段战斗阶段、主攻方变化、场地变化、环境反馈强度做局部重写，不能所有条目完全同文复制。
- **模板E新增时长规则**：若用户给出`单个提示词总时长`（当前前端固定为 `10s / 15s / 20s / 30s`），则该值只对模板E生效，并且必须作为**单条Seedance提示词的结构规划参数**使用。它不是简单改秒数，而是要求重算：每条提示词承载的情节段数、生成镜头数量、镜头长短配比、动作链长度、情绪停顿长度、铺垫与爆点位置。单集总时长用于算整集需要多少条提示词；单个提示词总时长用于决定每条提示词内部怎么设计。
- **模板E时长分桶设计铁律**：
  - `10s`：每条提示词通常承载 `2-4` 个生成镜头，只保留一个核心情节功能或一个微反转，单场景单重心优先，铺垫必须短，禁止塞完整多轮争执或完整来回攻防。
  - `15s`：每条提示词通常承载 `3-5` 个生成镜头，允许完成一次小型“铺垫→冲突/推进→落点”，适合大多数标准Seedance直出。
  - `20s`：每条提示词通常承载 `4-6` 个生成镜头，允许加入更完整的因果链、一个明显反转点或更完整的情绪停顿，但仍需保持单场景主重心。
  - `30s`：每条提示词通常承载 `5-8` 个生成镜头，只在 Seedance 2.5+ 或明确长生成场景优先使用，允许更完整的连续动作链、双节拍转折或更长的文戏留白，但必须控制在同一主场景/同一主事件内，避免把多段大情节生硬拼进一条提示词。
- **模板E单镜时长强规则**：`10s / 15s / 20s / 30s` 控制的是**单条提示词总时长**，不是单个生成镜头时长。模板E内部的**单个生成镜头一般不要超过 4 秒**，这是强规则。若总时长变长，优先做法是**增加生成镜头数量、补充节拍层次、增加铺垫或反应镜**，而不是把某一个镜头直接拉长到 5 秒、6 秒甚至更长。只有极少数明确长镜头感、且动作链连续、且画面重心稳定的镜头，才允许谨慎接近 4 秒上限。
- **模板E分条规则**：若用户同时给出`单集总时长`与`单个提示词总时长`，则先按单集总时长做总节奏规划，再按单个提示词总时长把整集内容切成若干条 Seedance 提示词。默认让每条提示词尽量贴近目标时长，末条允许略短；若尾段太短，则允许回并到上一条，但必须同步重构上一条的镜头数量和节奏密度，不能只在结尾多塞一句。
- **模板E分条数量强规则**：若用户同时给出`单集总时长`与`单个提示词总时长`，则模板E必须先计算：`提示词条数 = 单集总时长 ÷ 单个提示词总时长`。能整除就按整除结果输出连续提示词条数，例如：`90s ÷ 15s = 6条`，`90s ÷ 30s = 3条`；不能整除则**向上取整**，最后一条允许略短，但仍必须把剩余剧情讲完。**严禁**只输出其中一条提示词，或只做一段示例，或让用户自己再拆。

### 步骤 7.5：规则冲突检测 + 压力测试

**一、20项自动检测**（调用 scripts/validate_shot.py）：
分镜数据整理为JSON数组→`validate_shotlist(shots, template, model_budget)`→输出每镜错误+警告→错误镜修正后重验→全通过进入步骤8。20项检测清单详见脚本docstring，内部执行不输出给用户（除非要求查看）。检测覆盖：空间锚矛盾/情绪跳跃/道具锁缺失/站位轴变化/状态锁不一致/光影断裂/声音断裂/空间锚缺失/状态锁缺失/道具不一致/景别跳跃/台词超限/音效超限/爆点配额/画外角色漏标/交接帧缺失/情绪越界/六层锁不完整/打斗运镜重复(规则4)/打斗特写超限(规则6)。

**二、压力测试**（调用 提示词-压力测试.txt）：
每镜提示词字数压力定级——🟢≤80%预算通过 / 🟡80-100%建议检查 / 🔴>100%已压缩+标注被砍字段+给用户选项(接受压缩/升级模型/拆分镜头)。截断优先级：先砍音效→环境→光影→色彩→特效→台词标注；不砍锁定标签/动作/角色锚定；保底主画面100字。全局压力报告在所有镜输出后汇总。红色镜才显示给用户，绿色/黄色不显示。**🔴压缩处理**：选择"接受压缩"后，被砍字段在该镜末尾标注 `[已压缩：音效/环境/光影数值]`，步骤8检查时跳过已压缩字段的合规检查。

### 步骤 8：可拍性与可生成性检查 `[8/9]`（静默执行，不产出可见输出）

**前置**：①步骤7.5的validate_shot.py输出（20项自动检测结果）作为本步骤输入——validate_shot报告的错误镜必须先修正再进入人工检查。②已压缩字段（步骤7.5🔴告警中被标注`[已压缩]`的字段）跳过对应检查项。③检查结果记录：每镜的检查结果（PASS/FAIL+问题项）写入该镜的内部状态标记，供步骤9缓存池和步骤10反馈闭环追溯。④**本步骤全部静默执行，不在输出文件或对话中展示检查表/验证结果/自检清单。不通过→修正分镜→重新输出，用户只看到最终成品。**

缓存池前置：LOCKED镜(影响范围外)跳过；MODIFIED/PENDING镜走完整六项。

| 检查项 | 调用库 | 内容 |
|--------|--------|------|
| ①可行性 | 生成检查与规避库.txt SECTION:A | 12条检查+10项否决 |
| ②失败规避 | 生成检查与规避库.txt SECTION:B + 提示词库-负面提示词.txt | 扫雷+急救级负面词追加 |
| ③空间连续性 | 空间连续性控制库.txt | 18项自检（六层锁完整/背景角色未省略/物理变化已延续/光影声音一致/交接帧存在） |
| ④转场系统 | 转场系统参数库.txt SECTION:H | 6项检查（类型匹配决策树/参数标注/前后镜衔接/空间连续性影响/模型兼容性/铁律合规）+景别≤2级跳+180°线法则 |
| ⑤钩卡质检 | 节奏与钩子设计库.txt SECTION:A | 9条质检（首帧反常物/3秒脸/7秒反转/15秒爆点/30秒留坑/集尾匹配/跨集兑现/台账/钩爆守恒） |

| ⑥b武戏专检 | 打斗弹药库_通用.txt + 番剧作画打斗弹药库.txt | 武戏场景追加：正文零禁用词（定格/停格/顿帧/静默/画面冻结/子弹时间/绝对静默）/峰值镜用白闪+震镜+径向模糊替代冻结/回合单元五拍完整/命中一拍四段齐备/空间单向推进无回原点/末镜爆闪收黑非静止/双递增曲线E1→E2→E3+S1→S2→S3→S4/首帧锚定（img2video时镜头1从参考图主体启动） |

不通过→修正→再交付。

**统一检查入口**：调用 scripts/run_all_checks.py 可一次性执行全部6项检查（validate_shot 20项 + 空间连续性 + 转场系统 + 钩子卡点 + 音效合规 + 负面词完整性），输出带✅/❌的汇总报告。CLI用法：`python run_all_checks.py --file shots.json --template B --model libtv`。

### 步骤 9：交付确认与迭代 `[9/9]`

**交付确认**（内部校验，不输出）：全镜通过步骤8 / 模板一致未混用 / 六层锁完整 / 钩子标注 / 弧线内部校验。
**交付输出**：文件=分镜本身。对话=一句话告知完成（如"N镜已输出，需要调整哪镜？"）。**禁止输出交付确认表/检查结果汇总/设计复盘/对比分析等任何元内容。**
**写缓存**：LOCKED镜写入 shots_locked.json。多集同时更新 episode_snapshot.json。

**迭代修改指引**（按修改类型确定影响范围）：

| 修改类型 | 影响范围 | 重跑步骤 |
|---------|---------|---------|
| 改表情(单角色) | 目标镜+下游1镜 | 5→8 |
| 改站位(单角色) | 目标镜+同场景后续镜 | 3.5→4→8 |
| 改道具/着装 | 目标镜+后续至道具变化 | 3.5→8 |
| 改台词 | 目标镜+下游1镜口型/情绪 | 5→8 |
| 改运镜 | 仅目标镜 | 6→8 |
| 改场景设定 | 该场景所有镜 | 3.5→4→8 |
| 调节奏 | 全量 | 2→3.5→4→5→6→7→8 |
| 增删镜头 | 插入点后全部 | 2→3.5→4→5→6→7→8 |
| 换模板 | 全部重排 | 7 |
| 换模型 | 字数预算调整 | 7(不影响LOCKED) |

**生成测试建议**：先拿1-2个关键镜（首镜+爆点镜）测试。不理想按失败规避库降级，禁止原样重roll。多镜拆段按交接帧协议处理。

**跨集快照**：完成一集→生成 episode_snapshot.json（末帧场景/角色位置·姿态·表情/道具·着装·损伤/光影/时间/氛围）→下集步骤3.6自动加载→物理状态原样继承。

### 步骤 10：生成后反馈闭环 `[反馈]`

> 用户生成视频后回来反馈结果时激活。不需要重新走步骤1-9，只需修正目标镜。

1. **反馈监听**：用户说出"生成完了/翻车了/崩了/镜X不行"等关键词时激活。读取 scripts/generation_log.json（存在→增量更新；不存在→新建）。
2. **结果解析**：提取镜号+结果状态（SUCCESS/PARTIAL/FAILED）+失败描述。无明确描述→问"具体什么问题？（脸/手/动作/穿模/颜色/其他）"。
3. **失败归类**：Read 生成反馈闭环.txt，按关键词表匹配失败类型→对接生成检查与规避库.txt SECTION:B 对应小节。
4. **修正建议**：按失败类型生成诊断+修正方案（降级方案/拆镜/加负面词/换景别/换模型），展示给用户选择。
5. **应用修正**：用户确认→修改目标镜提示词→目标镜降为MODIFIED→查dependency_chains确定影响范围→影响范围内镜重跑步骤8→通过后重新标LOCKED。长生成模型（P4长生成级）优先使用局部编辑指令修正（时间戳定位+局部修改），避免整镜30秒重生成。
6. **经验积累**：更新 generation_log.json（shot_history/stats）。同类型失败2次→写入model_profile.weaknesses。同修正有效2次→写入project_patterns。新一集开始时自动读取model_profile预防性加固。
7. **循环**：修正后用户重新生成该镜→回来反馈→直到全部SUCCESS。

**预防性加固**：新一集步骤1开始前，如存在generation_log.json，读取model_profile.weaknesses和project_patterns，在步骤4/5/6中预防性应用（如已知模型手部弱→步骤6所有手部特写预设降级方案）。
