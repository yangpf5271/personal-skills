# 0-1 模式:从零到一份 video-spec.md

> 0-1 模式(项目里没有 video-spec.md)时读本文件。问题怎么问翻 `references/question-bank.md`,话怎么说翻 `references/dialogue-style.md`。Phase 1-5 是你内部的追踪,嘴上永远不说"Phase"(SKILL.md [不暴露内部 Phase])。

---

## Phase 1 · 基本盘(必问 gate)

**目标**:七个维度全部落地——视频目的 / 目标受众 / 平台与时长 / 核心信息 / 信息密度 / 品牌 Tone of Voice / 观众熟悉度。这是 spec 的地基,§ 0 元信息和 § 1 核心信息全部从这里来。

**进入条件**:用户说完开场描述(让他倒完,不打断)。

**动作**:
1. 从用户已说的内容里抽取七维度的答案,复述确认——不机械问一遍(SKILL.md [渐进式追问纪律])。
2. 缺哪个问哪个,每次只问 1-2 个,翻 `references/question-bank.md` Phase 1 的主问题。
3. 用户答"高大上 / 都行 / 你看着办" → 直接翻该维度的 [不接受的答案],拒绝并换问法。

**衔接范本(承上启下)**:
- 进入:"好,你这视频的基本盘我们捋一遍。"
- 推进:"还差两个:这视频给谁看、在哪发。回完这两个我们就可以挑节点了。"

**[充足度判断]**:
- 齐 = 七维度每个都有"可写进 spec 的具体答案"(不是形容词)。逐个对照 question-bank Phase 1 的 [接受标准]。
- 没齐时:同一维度换角度问第二遍(换问法,不是复读);用户真不知道 → 走方案引导给 2-3 个选项(翻 `references/dialogue-style.md` [方案引导]);绝不替用户决定卖点/受众/平台。
- 受众说"所有人"、时长说"大概一两分钟"、核心信息说不出来 → 一律不算齐。

**出口条件**:七维度全齐,且复述一遍用户点头。

---

## Phase 2 · 素材盘点

**目标**:摸清手里有什么——逐字稿 / 旁白音频 / 视频影像 / 图形 / 3D / 数据 / 配乐 / 待搜索素材。spec § 2 素材清单从这里来。

**进入条件**:Phase 1 出口。

**动作**:
1. 按 逐字稿 → 音频 → 视频 → 图形 → 数据 → 3D 的顺序逐项盘问(SKILL.md [素材盘点]),不让用户漏报。
2. 缺的素材当场判断:能否 TTS 生成 / 程序化生成 / 需要上网搜(SKILL.md [联网优先]:提到具体品牌/产品就去查)。
3. 有逐字稿 → 预告"后面我把它拆成一镜一镜"(引 `references/scene-breakdown.md`)。

**衔接范本**:
- "基本盘齐了。接下来盘家底——你手里已经有什么材料?"
- "逐字稿有了,那配音你是自己录,还是我帮你生成?"

**[充足度判断]**:
- 齐 = § 2 素材清单七行每一行都有明确状态(已有 / 待生成 / 待搜索 / 不需要)。
- 没齐时:不是追用户,是你补判断——待生成的素材必须对应能力对照表内的一项(P-8 校验),做不到的直接说做不到。

**出口条件**:素材清单七行全有状态,且没有"待生成但做不到"的死项。

---

## Phase 3 · 镜头语言与节奏

**目标**:定 场景类型组合 / 文字呈现 / 动效语言 / 节奏基准 / 叙事节拍 / 情绪曲线 / 音画关系。spec § 3 motion 列、§ 5、§ 6 从这里来。

**进入条件**:Phase 2 出口。

**动作**:
1. 按视频类型裁剪问题(产品演示重点问 3D + UI mock,翻 question-bank [按视频类型分流])。
2. **能力激发**(核心特色):对照 SKILL.md [能力对照表],扫出用户没提但相关的 1-2 项能力,用"它能让画面变成什么样"告知。具体问法翻 question-bank Phase 3 的能力激发追问示例。
3. 节奏基准翻 `references/pacing-rules.md`,按视频类型选基准。
4. 音画关系:旁白驱动 / 配乐驱动 / 静默设计,逼用户选一个。

**衔接范本**:
- "材料齐了,聊聊这片子长什么样、动起来什么感觉。"
- "先说说你这片子是字带着走,还是画面带着走?"

**[充足度判断]**:
- 齐 = 节奏基准有数值(如 ASL 2-4s);音画关系三选一落定;至少一个开场钩子的做法说得出口(0-7s 观众凭什么留下)。
- 没齐时:钩子说不出 → 给 2-3 个钩子方案(翻 dialogue-style [方案引导]);情绪曲线说不出 → 用"起-伏-起"三段式带着用户填。

**出口条件**:节奏基准 + 音画关系 + 钩子雏形三样落定。

---

## Phase 4 · 视觉风格

**目标**:定 主题 / accent 色覆盖 / 装饰层密度 / 组件白黑名单。spec § 4 从这里来。

**进入条件**:Phase 3 出口。

**动作**:
1. 报 8 个预设的一句话标签(翻 question-bank Phase 4),让用户挑;或走自定义 design.md 路径(用户描述三个形容词/参考品牌 → 上网调研 → 在项目根生成 design.md,格式见 SKILL.md [主题选择])。
2. 用户敷衍"随便" → 强制走描述生成,逼出三个形容词。
3. **主题一旦定下,颜色/字体/字重/动效/间距/圆角全部跟着定,不再回头问**(SKILL.md [视觉风格的处理])。只问可调三项:accent 覆盖 / 装饰层密度 / 组件白黑名单。
4. 检查项目根有没有 design.md / DESIGN.md(启动检查第 2 步的延迟消费点)。

**衔接范本**:
- "动的感觉有了,现在定长相。八个现成风格,我一个个说给你听。"

**[充足度判断]**:
- 齐 = theme 字段落定(预设名或 design.md);可调三项至少各有答案("无"也是答案)。
- 没齐时:给预设标签时附参考画面感;自定义路径下用户形容词还在飘 → 追问"这三个词放到画面上,第一眼看到的是什么"。

**出口条件**:theme 落定。若自定义:design.md 已生成在项目根(P-2 校验)。

---

## Phase 5 · 参考对齐

**目标**:收集 参考视频 / 静态参考 / 反例 / 同质化反例,给 spec 的 hook、情绪曲线、§ 8 包装校准方向。

**进入条件**:Phase 4 出口(此阶段快,常常 2-3 个问题就完)。

**动作**:
1. 问"有没有看过觉得'就要这种感觉'的片子";用户说"X 感" → 翻 `references/dialogue-style.md` [影视参考词典] 对译成具体作品。
2. 问反例:"有没有绝对不要的?"——反例和正例一样值钱。
3. 用户给了链接/品牌 → "我去上网查一下",真去搜(SKILL.md [联网优先])。

**衔接范本**:
- "最后对个表:你脑子里有没有一部'照着这个感觉来'的片子?"

**[充足度判断]**:
- 齐 = 正反参考至少各一条,或用户明确说"没有,按你说的来"。
- 没齐时:主动从影视参考词典里抛 2-3 个候选让用户挑。

**出口条件**:参考收集完,信息足以起草。

---

## 起草 video-spec.md

1. 读 `references/spec-rules.md`(字段约束 + P 系列校验 + 自检清单)和 `../templates/video-spec-template.md`。
2. 按 § 0 → § 9 顺序填:
   - § 0 元信息 ← Phase 1(+fps/aspect 跟随 platform)
   - § 1 核心信息 ← Phase 1(三个关键信息点此时先写内容,镜头号等 § 3 完成后回填)
   - § 2 素材清单 ← Phase 2
   - § 3 分镜表 ← 按 `references/scene-breakdown.md` 拆解;component 对照 `references/components-catalog.md` 选 `C<nn>`
   - § 4 视觉规范 ← Phase 4
   - § 5 音频设计 ← Phase 2 + Phase 3
   - § 6 节奏与结构 ← Phase 3 + Phase 5(钩子三层镜头号回填)
   - § 7 claim log ← 从 voiceover 里抽原子断言,逐条定状态
   - § 8 平台包装 ← Phase 1 platform + Phase 5
   - § 9 待确认项 ← 所有推断内容标 `[待用户确认]`(失效 4 防御:不默默填)
3. 过 spec-rules § 3 自检清单 + P-1 ~ P-8。不过的回去补问,不自作主张填空。
4. 把 spec 的关键决策复述给用户:镜头数、总时长、钩子、待确认项——让他过目。§ 9 清零(或用户说留着)后 status 才可写 locked。
