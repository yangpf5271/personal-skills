# 7 角色审查清单（可判定版）

> 每条检查项必须回答 yes/no，或给出 video-spec.md 中的具体字段/镜头号作为证据。禁止无锚点评。
> `[gate]` = 必过项：未过即该角色判定失败，对应发现直接进汇总清单的 🔴 区。
> 章节引用（§0-§9）与字段名以 `../video-spec-builder/templates/video-spec-template.md` 为权威；跨字段校验规则（P-1~P-9）见 `../video-spec-builder/references/spec-rules.md`。

## 0. 使用说明

- 阶段判断：分镜表（§3）status 全为 outline → 只走角色 1/2/6/7（审纸面）；出现 built/animated → 加审角色 3/4/5（审实现）。但纸面 gate（component 锚定/P-2/P-8）由前置采集统一执行，不受阶段限制。
- 每条发现必须标注锚点：镜头号（如 #3）或 spec 字段（如 §0.message、§6 钩子三层）。
- 评分必须引用本文件对应角色的评分锚点，说明落在哪一档、为什么。

## 1. 选题策划 — "这个选题本身站得住吗"

### 检查项
- [gate] §0.message 能否填进 "This video tells [audience] that [___]" 且一句话不换行？填不进去 = 命题未成立。
- [gate] §0.audience 是否具体人群 + 场景？"所有人 / 大众 / 程序员"这种宽泛答案不过关。
- [gate] §1 承诺对照表每条承诺是否都有兑现镜头号，且该镜头在 §3 分镜表中存在（P-5）？任何一条悬空即 fail。
- §1 三个关键信息点是否按重要性排序、各标了兑现镜头号（P-4）？第一信息点是否出现在前 30% 时长内？
- 信息差：对照 §3 的 info_payload 列，能否指出至少一个"目标观众看完学到/看到新东西"的镜头？全是常识复述即扣分。
- 差异化（wow factor 检验）：能否回答"还有谁能做出这个视频"并举出具体镜头（如 #4 的呈现方式）？答不出 = 同质化风险。
- §9 待确认项：status=locked 时残留即扣分（gate）；status=draft 时仅提示不扣分。残留的 `[待用户确认]` 说明选题还有未裁决的假设。

### 评分锚点
| 分段 | 状态 |
|---|---|
| 0-3 | message 填不进句式，或承诺对照表存在悬空条目（gate 未过即封顶 3 分） |
| 4-6 | 命题成立，但三个信息点兑现牵强、信息差弱，观众看完说不出"跟我有关系" |
| 7-9 | 承诺逐条兑现、有明确信息差，缺一个"只有这个视频才给得了"的差异化桥段 |
| 10 | 一句话命题立得住 + 承诺逐条兑现 + 能指认具体镜头回答"还有谁能做出这个" |

## 2. 事实核查 — "每个说法站得住吗"

### 检查项
- [gate] §7 claim log 存在且每条为原子断言（单一、自包含、可独立判定真假）？复合句（"X 快了 30% 而且最便宜"）必须拆开。
- [gate] 无"待核"状态的 claim；无 `false` 状态的高优先级 claim。
- [gate] voiceover / scene 中不存在无主语引用（"研究表明 / 专家表示 / 据统计"）——出现即 fail，必须补来源或删除。
- 每个 `unverifiable` 的 claim，对应 voiceover 是否改为留有余地的措辞（"据 X 称" / "截至 Y 年"）？
- 高优先级 claim（重要性高 × 可证伪 × 有争议）是否都标 `verified` 且附一手来源（原始论文/官方数据，而非转述媒体）？
- 联网核实（SIFT）：最惊人/最反直觉的 1-3 条 claim 是否逐条做了"来源是谁 → 有没有更好的覆盖 → 原始语境是否断章取义"？
- 时效性：涉及数字/版本号/产品定价的 claim，来源是否是一年内的？逐条列出过期项。

### 评分锚点
| 分段 | 状态 |
|---|---|
| 0-3 | §7 缺失/无主语引用存在/高优先级 claim 有 false（gate 未过即封顶 3 分） |
| 4-6 | 有 claim log 但断言不够原子，或中优先级 claim 来源是二手转述 |
| 7-9 | 全部定级且高优先级均 verified，个别中低优先级来源偏弱 |
| 10 | 全部原子化、定级、一手来源，且反直觉表述已优先核实过 |

## 3. 技术实现 — "开发者视角，这能跑吗"

### 与 CLI 的分工（先声明，不重复劳动）
代码层检查**委托**给工具，本角色只引用其结果，不自己重做：
- 结构（composition-id / 轨道冲突 / 时间线注册）→ `npx hyperframes lint`
- 对比度（WCAG 4.5:1，大字 3:1）→ `npx hyperframes validate`
- 溢出/裁剪/出画布 → `npx hyperframes inspect`（`--json` 供读取）
- 编排（dead zones >1s 无动画、paced-fast <0.2s / paced-slow >2s）→ hyperframes 的 `scripts/animation-map.mjs`

### 本角色只审 spec 层
- [gate] §3.component 每个值都是 catalog 内存在的 `C<nn>` 组件 ID？写不出组件的镜头应标 `[待确认]` 进 §9——静默悬空即 fail。
- [gate] §2 标"待生成"的素材，对应能力在能力对照表内（`../video-spec-builder/SKILL.md` [能力对照表] 一节，P-8）？表里没有的能力（如"AI 生成 3D 人物动作"）= 当前方案做不了。
- [gate] P-1：§0.aspect 与 platform 匹配（bilibili/youtube 主 16:9；douyin/xiaohongshu 主 9:16）；P-2：theme = design.md 时该文件实际存在于项目根。
- 素材链路：§2 素材状态 vs §5 音频设计是否一致（§5 写了 TTS 但 §2 逐字稿标"不需要" = 断点）？断电点逐条列出。
- 硬性约定前置检查（spec 阶段就能预判的违例）：§3.motion 是否暗示了无限循环（对应渲染层禁 `repeat:-1`）、随机变化（禁 Math.random/Date.now）；多镜头视频 transition_in 是否每镜都有且首镜 hard cut。
- 性能预算：统计 §3 中 3D/shader/粒子类 component 的镜头数与 duration——Three.js 镜头占比 >50% 或 §0.fps=60 且 duration_total >120s 时，渲染时长与掉帧风险要提示。

### 评分锚点
| 分段 | 状态 |
|---|---|
| 0-3 | 存在悬空 component / 能力对照表外的效果 / P-1、P-2 违例（gate 未过即封顶 3 分） |
| 4-6 | 全部可行，但素材链路有断点或硬性约定有预判违例，需要改 spec 才能落地 |
| 7-9 | 全链路可跑，性能预算贴边（3D 镜头多 / 60fps 长片），建议降档但不阻塞 |
| 10 | component 全锚定、素材链路无断点、无预判违例、性能余量充足 |

## 4. 视觉设计 — "看起来对不对"

### 分阶段
- **spec 阶段（分镜全 outline）**：只审 §4 一致性。
- **composition 阶段（有 built/animated）**：审实际 compositions HTML，逐镜执行下列六类检查（移植自 design-adherence）。

### spec 阶段检查项
- [gate] §4.theme 与 §0.theme 一致；theme = design.md（项目根目录）时 design.md 实际存在（P-2）——否即阻塞项。
- §4.accent 覆盖是主题的合法可调维度（不在字体/字重/圆角上做覆盖——那些已被 theme 定死）。
- §3.scene 每镜一句话写"观众看到什么"且主焦点唯一？"不知道该看哪"的镜头列出来。

### composition 阶段检查项（六类，逐镜判定）
- [gate] **Colors**：该镜 HTML 里每个 hex 都 ∈ design.md/预设的 palette？任何"发明的颜色"逐个列出（selector + hex）。
- [gate] **Typography**：字体族和字重与 design.md 声明完全一致，无替换字体？
- **Corners**：border-radius 匹配声明的 corner style？
- **Spacing**：padding/gap 落在声明的密度区间（§4.装饰层密度）内？
- **Depth**：阴影用法匹配声明的深度级别（flat=无阴影 / subtle=轻阴影 / layered=glow）？
- **Avoidance**：design.md 的 Don'ts / 反模式逐条验证不存在？
- 对比度与溢出**委托** `npx hyperframes validate` / `inspect`，本角色引用其输出，只补"灰字铺灰底"这类工具采样点之间的目测嫌疑。
- 手机尺寸可读性：§0.platform 为 douyin/xiaohongshu（9:16）时，文字是否在小屏可读（手臂距离测试）？

### 评分锚点
| 分段 | 状态 |
|---|---|
| 0-3 | theme 不一致 / design.md 缺失 / Colors 或 Typography 有违例（gate 未过即封顶 3 分） |
| 4-6 | 六类中 Corners/Spacing/Depth/Don'ts 有零星违例，或个别镜头主焦点不唯一 |
| 7-9 | 六类全过，信息层级清晰，个别镜头的目测对比度存疑 |
| 10 | 六类零违例 + 每镜一眼看到主焦点 + 小屏可读无虞 |

## 5. 审美品味 — "好不好看，高不高级"

### 检查项
- [gate] 无"廉价感"默认值：全片（spec 的 §4 + 各镜 HTML）不出现 `#333`、`#3b82f6`、`Roboto` 这类 lazy defaults，也无 8 预设之外的拼凑配色。出现即拉低档次。
- [gate] 风格可追溯：全片用到的 hex / 字体族都能追溯到 §0.theme 这**一个**来源？"大杂烩"（前半 Swiss 后半毛玻璃）即 fail。
- §3.scene / §4 中不存在只靠形容词的审美指令（"高级感的画面"、"电影感"）——每个审美要求是否翻译成了具体参数（色板/字号梯度/留白比例）？
- 删减测试：任选一段（连续 2-3 镜），删掉它观众损失什么？答不出损失的段落进删减候选。
- 全片至少有一个"值得截图 / 值得转述给别人"的时刻（对应镜头号）？指不出来 = 平庸。
- 信息密度：对照 §4.装饰层密度，是否有"拥挤到窒息"或"空旷到无聊"的镜头区间（标镜头号范围）？
- 开头承诺与结尾交付是否形成闭环（§1 信息点在结尾镜头有回扣）？

### 评分锚点
| 分段 | 状态 |
|---|---|
| 0-3 | lazy defaults 出现 / 风格不可追溯到单一 theme（gate 未过即封顶 3 分） |
| 4-6 | 风格统一但平庸：无违例也无记忆点，删减测试能删掉 2 个以上段落 |
| 7-9 | 统一且有至少一个值得截图的时刻，个别区间密度失衡 |
| 10 | 单一来源的风格 + 每段经得起删减测试 + 至少一个高光时刻 |

## 6. 节奏控制 — "观众会不会中途划走"

### 数值先行（从 §3 分镜表算，不凭感觉）
- [gate] P-3：§0.duration_total ≈ Σ duration（±10%）？P-7：voiceover 总字数 × 语速（中文 4-5 字/秒）≈ 含旁白镜头的 duration 之和？对不上即节奏账本不平。
- 单镜对账：每镜 voiceover 字数 ÷ 该镜 duration ≤6 字/秒，超出的镜头点名（全片总量合格但单镜爆字仍算 fail）。
- [gate] §3 无空帧：每镜 info_payload 至少承载 文案/数据/视觉冲击/节奏点 之一；≥4s 镜头的 info_payload 经得起"这 4 秒在表达什么"的追问；≤1s 镜头有强视觉刺激。
- [gate] §6 钩子三层齐备且镜头号真实存在：0-7s 确认点对视频 → #n；8-30s 讲什么+为什么是你 → #n；开环 → #n 开、#n 关（P-6）。开环没关 = 结构性缺陷。
- ASL 对账：Σ duration ÷ 镜头数，落在 §6.节奏基准声明的区间内（口播类 15-25s、动效类 2-4s）？统计偏离 ±50% 的区间标出来。
- 镜头时长有变化：是否存在连续 ≥3 个等长镜头（催眠效应）？列出镜头号。
- 节奏重置点：§6 是否按"每 2-3 分钟 / 短视频每 30s"安排了重置（快切/场景切换/图形插入）？短视频可写"不适用，总长 <Ns"——但要核对总长确实短。
- 情绪曲线：§6 的起-伏-起段落是否映射到具体镜头区间？全高能（麻木）或全平淡（划走）都标出来。
- 结尾处理：最后 1-2 镜是否有明确收尾 + 引导（对照 §8.结尾引导）？
- 成品阶段（有 animated）：引用 `animation-map.mjs` 的 flags——dead zones（>1s 无动画）、paced-fast（<0.2s）、paced-slow（>2s）逐条映射回镜头号。

### 评分锚点
| 分段 | 状态 |
|---|---|
| 0-3 | P-3/P-7 对不上账、有空帧、或开环没关（gate 未过即封顶 3 分） |
| 4-6 | 账本平但钩子三层缺层，或存在明显拖沓段（>25s 无切换无新信息） |
| 7-9 | 三层钩子齐、ASL 对账，个别区间节奏均质或缺重置点 |
| 10 | 数值全对账 + 钩子三层齐 + 时长有变化 + 重置点到位 + 结尾闭环 |

## 7. 平台包装 — "§0.platform 的观众买不买账"

按 §0.platform 分支，不硬编码任何平台。

### 通用检查项（所有平台）
- [gate] P-1：aspect 与 platform 匹配（bilibili/youtube 主 16:9；douyin/xiaohongshu 主 9:16）。
- [gate] §8 六个字段（标题/封面/描述前两句/章节时间戳/结尾引导/发布设置）无空缺；"不适用"必须带一句理由。
- 标题朗读测试：读出声——"引发好奇但不误导"？标题承诺是否与 §1 承诺对照表同源（不是两套话术）？
- 封面三要素：主视觉 + 标题文字 + 情感信号齐吗？核心元素 ≤3 个？手机尺寸下能看清吗？
- §8.描述前两句是否承载关键词与内容概述（不是"大家好欢迎关注"）？

### 分支检查项
**bilibili（§0.platform = bilibili）**
- 前 15 秒（对照 §3 前 1-3 镜）能不能让人不走？B 站完播率的生死线在前 15 秒。
- 封面内容与视频内容相关（平台合规红线），大字标题、高对比、关键信息前置。
- 片尾三连引导（点赞/投币/收藏）是否落在 §8.结尾引导并映射到最后镜头？
- §8.发布设置：分区/标签/合集归属/分P（若有）逐项核对？弹幕预判：哪些画面会被刷"？？？"或"哈哈哈哈"（可加分项，用于预埋互动点）。

**douyin / xiaohongshu（§0.platform = douyin | xiaohongshu）**
- 前 3 秒（对照 #1 镜）有没有钩子？信息流算法只看 3 秒留存，"讲座式开场"直接划走。
- 9:16 竖屏安全区：文字/关键信息是否避开顶部账号栏与底部文案栏（对照 §3.scene 描述）？
- 节奏基准核对：§6 是否按短视频节奏（ASL 明显短于口播长视频、重置点每 30s）设置？
- §8.章节时间戳应写"不适用"（短视频无章节）——写了反而是没想清楚。

**youtube（§0.platform = youtube）**
- 标题关键词前置；避免大写滥用和 emoji 堆砌（官方建议）。
- 缩略图手臂距离手机测试；准备 A/B 备选封面（§8 是否提到）？
- 章节时间戳：每章有独立可点击的价值点，且与 §6 节奏重置点对得上？
- 结尾卡/end screen 是否指定了引导去的具体视频/播放列表（不是泛泛"关注频道"）？

### 评分锚点
| 分段 | 状态 |
|---|---|
| 0-3 | P-1 违例 / §8 有静默空缺 / 平台分支的"前 N 秒"检查失败（gate 未过即封顶 3 分） |
| 4-6 | 字段齐但标题封面平庸，或承诺与 §1 不同源，读者扫一眼不想点 |
| 7-9 | 三要素齐、平台专项全过，缺 A/B 封面或弹幕/互动预埋这类加分动作 |
| 10 | 平台分支逐项全过 + 标题封面与 §1 同源 + 互动点已预埋到具体镜头 |

## 审查元规则

1. **意见必须带锚点**：每条发现标注镜头号（#n）或 spec 字段（§x.y），可映射回 video-spec.md 行级。给不出锚点的意见不输出（抑制泛泛点评）。
2. **只诊断，不命令**：描述问题（"#3 到 #5 连续 12 秒没有信息增量"），不直接下命令改法（"把 #4 删了"）。是否采纳、怎么改，归创作者决定。
3. **裁决权归用户**：7 个角色平等给 notes，但没有谁有权否决——你是 Braintrust，不是导演。冲突意见并列呈现，让用户裁决。
4. **25%-75% 时机法则**：审查在"spec 定稿后、渲染前"最有价值——太早（想法阶段）无法有效评估，太晚（渲染完）改不动。
5. **gate 未过进 🔴**：任何角色的 `[gate]` 检查失败，对应发现直接进汇总清单的"必须改"，不受该角色总分高低影响。
6. **推测必须标注**：前置信息（§0.audience/platform/message）缺失时打的分数标"⚠️ 推测值"，并说明补齐哪个字段后可转为实分。
