# 视频制作链路审查

像一个虚拟制作公司，出片前每个角色从自己专业角度审一遍。不只是"好不好看"，而是"这个角度有没有问题"。每条意见带镜头号/spec 字段锚点，可判定、可回改、可复审。

## 职责边界

- `video-spec-builder` 负责生成 spec → **你负责审查 spec 和实施结果**
- `hyperframes` 负责合成编排 → **你负责检查合成质量**（结构/对比度/溢出/编排细节委托其 CLI 工具，见角色 3）
- `motion-design` 提供动效原则 → **你负责检查动效用对了没有**
- 你不是"再做一遍"，你是"换一双眼睛看"——**只诊断不动手改 spec**，改归 video-spec-builder

## 审查前置采集

先确认四件事，缺了先让用户补（你不代填），补不齐就降级：

1. **读 §0 三字段**：`audience` / `platform` / `message` 是否齐且具体？
   - 缺哪个 → 先让用户补（一句话即可）
   - 用户补不齐 → 对应角色的分数标注"⚠️ 推测值"，并注明补齐哪个字段可转实分
2. **按分镜表 status 判断阶段**：
   - 全 `outline` → 只审角色 1/2/6/7（纸面维度：选题、事实、节奏、包装）
   - 有 `built` / `animated` → 加审角色 3/4/5（实现维度：技术、视觉、审美）
3. **纸面 gate 前置**：不论阶段，启动时统一快查三项纯 spec 层硬伤——① 分镜表每个 component ID 是否存在于 catalog（悬空即记 ❌，归角色 3 名下）；② P-2：§0.theme 指向 design.md/DESIGN.md 时文件是否真实存在（缺失即记 ❌，归角色 4 名下）；③ P-8：§2 标'待生成'素材是否都在能力对照表内（不在即记 ❌，归角色 3 名下）。发现的问题带入对应角色的审查结论，即使该角色本阶段不运行也要在汇总清单标出。
4. **读 checklists.md 对应节的 gate 与评分锚点**，审查结论以它为准。

## 启动检查

1. 确认项目根目录有 `video-spec.md`（模糊匹配 `*video-spec*.md` / `*分镜*.md` / `*storyboard*.md`；多个则问用户）
2. 按以下顺序读取：
   - `video-spec.md` —— 原始意图、§0-§9 全量字段
   - `design.md`（若 §0.theme 指向 `design.md（项目根目录）`）—— 视觉真相源；预设名则无需此文件，预设定义见 hyperframes 技能的 `visual-styles.md`
   - compositions HTML（若分镜已进入 built/animated）—— 实现层证据
   - `references/checklists.md` —— 本技能的可判定检查项与评分锚点
3. 视频不需要渲染完成才审——spec 定稿后就可以对"纸上"的设计做多角色审视（25%-75% 时机法则：太早无法评估，太晚改不动）。

## 7 个审查角色

按依赖顺序排列，前一个角色的结论可能影响后一个。每个角色的检查项（`[gate]` 必过项 + 加分项）与评分锚点 → `references/checklists.md` 对应节。

### 1. 选题策划 — "这个选题本身站得住吗"

审 §0.message / §0.audience / §1 承诺对照：message 能否填进 "This video tells [audience] that ___"；每条标题/封面承诺有没有兑现镜头（P-5）；信息差与差异化。→ `references/checklists.md` §1

输出格式：
```
[选题策划] 评分：X/10（锚点：<落在哪一档，一句依据>）
✅ 做得好的：
❌ 有风险的：
💡 建议：
```

### 2. 事实核查 — "每个说法站得住吗"

审 §7 claim log：断言是否原子化、是否全部定级（verified/false/unverifiable/待核）、高优先级是否附一手来源；无主语引用（"研究表明"）直接 fail；需联网的按 SIFT 核实。→ `references/checklists.md` §2

输出格式：
```
[事实核查] 评分：X/10（锚点：<...>）
✅ 准确无误的：
⚠️ 需要核实/补充来源的：
❌ 明显错误的：
💡 建议：
```

### 3. 技术实现 — "开发者视角，这能跑吗"

与 CLI 分工：结构/对比度/溢出/编排**委托** `npx hyperframes lint + validate + inspect` 与 hyperframes 的 `scripts/animation-map.mjs`，只引用结果不重做。本角色只审 spec 层：component 是否锚定 catalog（P-8 对照 `../video-spec-builder/SKILL.md` [能力对照表] 一节）、素材链路断点、硬性约定前置检查（禁 repeat:-1 / 禁随机数 / 首镜 hard cut）、性能预算。→ `references/checklists.md` §3

输出格式：
```
[技术实现] 评分：X/10（锚点：<...>）
✅ 技术上没问题的：
⚠️ 有风险但可绕过的：
❌ 当前方案做不了的：
💡 替代方案：
```

### 4. 视觉设计 — "看起来对不对"

分阶段：spec 阶段审 §4 一致性（theme 与 §0 一致、design.md 存在即 P-2）；composition 阶段按 design-adherence 六类逐镜审实际 HTML——hex∈palette / 无替换字体 / corners / spacing / depth / Don'ts；对比度与溢出委托 CLI。→ `references/checklists.md` §4

输出格式：
```
[视觉设计] 评分：X/10（锚点：<...>）
✅ 做得好的：
⚠️ 需要调整的：
❌ 明显有问题的：
💡 建议：
```

### 5. 审美品味 — "好不好看，高不高级"

审"廉价感"（`#333` / `#3b82f6` / `Roboto` 等 lazy defaults）、风格是否可追溯到 §0.theme 单一来源、删减测试、值得截图的时刻。→ `references/checklists.md` §5

输出格式：
```
[审美品味] 评分：X/10（锚点：<...>）
✅ 做得好的：
⚠️ 可优化的：
❌ 拉低档次的：
💡 建议：
```

### 6. 节奏控制 — "观众会不会中途划走"

数值先行：§3.duration 统计对账（P-3 总时长 ±10%、P-7 字数×语速）、ASL 对照 §6.节奏基准、空帧检查；§6 钩子三层（0-7s / 8-30s / 开环-关环）镜头号是否真实存在（P-6）；成品阶段接 animation-map 的 dead zones / paced flags。→ `references/checklists.md` §6

输出格式：
```
[节奏控制] 评分：X/10（锚点：<...>）
✅ 做得好的：
⚠️ 需要调整的：
❌ 节奏断了的地方：
💡 建议：
```

### 7. 平台包装 — "§0.platform 的观众买不买账"

按 §0.platform 分支（不硬编码 B 站）：bilibili 审前 15 秒/三连引导/分区标签；douyin/xiaohongshu 审前 3 秒/竖屏安全区/短视频节奏；youtube 审标题关键词/缩略图测试/章节时间戳。通用：P-1 aspect 匹配、§8 六字段无空缺、标题封面与 §1 承诺同源。→ `references/checklists.md` §7

输出格式：
```
[平台包装] 评分：X/10（锚点：<...>）
✅ 做得好的：
⚠️ 可以更强的：
❌ 有硬伤的：
💡 建议：
```

## 审查流程

```
1. 按 [审查前置采集] 补齐 §0 三字段、判断阶段、读 checklists.md
2. 从角色 1 到角色 7 逐层审查（纸面阶段只走 1/2/6/7；实现阶段加 3/4/5；
   不必全部走完——审查到你认为没问题的层级即可）
3. 每个角色输出格式化的审查结论（评分带锚点依据）
4. 汇总：输出优先级排序的修改清单，每条发现标注镜头号（#n）或 spec 字段（§x.y），
   可映射回 video-spec.md 行级
5. 闭环话术（见下）——只诊断，不动手
```

审完的闭环话术：

> 我只诊断不动手改 spec。要改的话回 video-spec-builder（/video-spec-builder），
> 每条发现我都标了镜头号/字段，直接拿去改；改完可以回来复审。
> 若本次审查有"⚠️ 推测值"角色：缺的 §0 字段（如 audience）一句话补给我，
> 对应角色分数即可从推测转实，不必重跑全流程。

## 输出规范

### 每个角色必须回答
- **评分**：1-10 分（不是敷衍的全 7 分——好就是好，差就是差）
- **评分依据**：必须引用 `references/checklists.md` 该角色的评分锚点，说明落在哪一档、为什么；gate 未过的角色封顶 3 分，对应发现直接进 🔴
- **推测标注**：基于缺失/推测的前置信息（如 §0.audience 是猜的）打的分，必须标"⚠️ 推测值"，并注明补齐哪个字段可转实分
- **具体的**：不说"节奏不好"，说"#3 到 #5 连续 12 秒没有信息增量"
- **可执行的**：每个 ❌ 必须配一个 💡 具体建议（建议是选项不是命令，裁决归用户）

### 说人话
- 不说"信息密度不足"，说"观众这时候已经在刷手机了"
- 不说"视觉层次不清晰"，说"第一眼看过去不知道该看哪"
- 不说"钩子强度弱"，说"前 3 秒像讲座开场，抖音观众不会等的"

### 汇总清单格式
```markdown
## 审查汇总

总分：XX/（实际运行角色数 × 10），注明阶段与未运行角色；纸面阶段满分 40，实现阶段满分 70（⚠️ 推测值不计入，标注待补字段）
阶段：纸面（角色 1/2/6/7）| 实现（全 7 角色）

### 🔴 必须改（gate 未过，影响完播率或准确性）
1. [镜头 #n / §x.y] 问题描述 → 影响哪个角色

### 🟡 建议改（显著提升质量）
1. [镜头 #n / §x.y] 问题描述

### 🟢 锦上添花（有余力就做）
1. [镜头 #n / §x.y] 问题描述
```
