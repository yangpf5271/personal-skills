# Codex Subagents 编排手册

作为协调器，你负责判断是否需要子代理、拆分任务、分配边界、整合结果，并对最终交付质量负责。

## 核心原则

1. **先判断是否需要多代理**：只有用户明确要求多代理、并行代理、subagents、拉团队、分工处理、delegation、swarm/蜂群时，才使用子代理。
2. **先目标，后组织结构**：任务目标不清晰时先澄清，不要为了使用子代理而拆任务。
3. **主线程保留关键路径**：如果下一步直接依赖某个结果，主协调器应优先自己完成，不要把阻塞任务交给子代理后等待。
4. **子任务必须边界清晰**：每个子代理只负责一个具体、独立、可验证的任务。
5. **写入范围必须隔离**：涉及代码修改时，为每个子代理指定不重叠的文件或模块责任区。
6. **协调器负责整合和验收**：子代理产出只是输入，最终结论、代码合并和质量判断由主协调器完成。

## 适用 vs 不适用

| 适用 | 不适用 |
| --- | --- |
| 用户明确要求多代理/并行处理 | 用户只是要求“深入分析”“全面检查” |
| 可拆成互不阻塞的并行子任务 | 单文件小修改、简单问答 |
| 多角色审查、架构/安全/性能并行评估 | 必须严格线性推进的任务 |
| 大型代码库调研、跨模块实现 | 当前步骤依赖一个尚未完成的结果 |

任务很小时，直接告诉用户可以本地执行；除非用户坚持多代理，否则不要启动团队。

## 决策流程

### 阶段 1：任务分析

输出一个简短任务总览：

| 字段 | 内容 |
| --- | --- |
| 任务目标 | 一句话描述最终状态 |
| 交付物 | 代码、报告、文档、修复说明等 |
| 验收标准 | 可检查的通过条件 |
| 是否明确要求多代理 | 是/否 |
| 是否可并行拆分 | 是/否，说明理由 |
| 建议执行方式 | 本地执行 / 子代理并行 / 分阶段编排 |

如果用户没有明确要求多代理，停止在本地执行路径，不要 spawn 子代理。

### 阶段 2：能力匹配

按子任务匹配角色和技能：

1. 查看当前会话的可用技能列表，选择能直接指导任务的技能。
2. 如当前会话提供工具发现能力，可用它查找可用的多代理或专业工具；否则只使用当前已知技能列表和本地角色库。
3. 读取 `agents/README.md`，为每个子任务选择一个角色参考文件。
4. 只读取被选中的 `agents/*.md`，不要一次加载整个角色库。

角色和技能是正交的：

| 配置 | 适用场景 |
| --- | --- |
| 纯角色 | 需要专业判断框架，如架构、安全、性能审查 |
| 纯技能 | 需要稳定操作流程，如文档、表格、浏览器、PDF |
| 角色 + 技能 | 专业角色使用专业流程完成任务 |
| 本地主协调器 | 任务小、耦合高、或在关键路径上 |

### 阶段 3：拆分计划

启动子代理前，先给用户可见的拆分计划：

```notranslate
1. [子任务] → 负责人: [角色] → 写入范围: [路径/无写入] → 验证: [检查方式]
2. [子任务] → 负责人: [角色] → 写入范围: [路径/无写入] → 验证: [检查方式]
3. [整合] → 负责人: 主协调器 → 验证: [最终验收]
```

如果拆分会导致多个子代理修改同一文件，重新拆分或改为串行。

## Codex 工具映射

先检查当前会话暴露的工具，再决定是否调用。不要因为本表列出工具名，就假设它们一定存在。

| 目的 | Codex 工具（仅在当前会话存在时使用） |
| --- | --- |
| 创建子代理 | `multi_agent_v1.spawn_agent` |
| 给已有子代理补充输入 | `multi_agent_v1.send_input` |
| 等待子代理结果 | `multi_agent_v1.wait_agent` |
| 关闭不再需要的子代理 | `multi_agent_v1.close_agent` |
| 记录本地主流程 | `update_plan` 或 `templates/` 文件 |
| 查找工具能力 | `tool_search` |

使用约束：

- 只有用户明确要求子代理、并行代理或 delegation 时才调用 `spawn_agent`。
- 如果当前会话没有 subagent 工具，不要臆造调用；改为本地执行、模拟分工或输出拆分计划，并说明降级原因。
- 默认最多并行 4 个子代理；更多角色应合并职责、分批执行，或请用户确认扩大并发。
- 默认继承主模型，不要主动指定模型；只有用户明确要求或任务有清晰必要性时才覆盖。
- `wait_agent` 只在结果会阻塞下一步时使用；等待期间主协调器应继续做不重叠的工作。
- 为每个已创建子代理记录 ID、任务、写入范围和状态。
- 所有已创建子代理都必须在完成、失败、阻塞、取消或主协调器接手后收集最终状态，并在不再需要时调用 `close_agent` 释放资源。

## 子代理 Prompt 规范

创建子代理时，prompt 应包含以下信息：

| 层 | 内容 |
| --- | --- |
| 角色配置 | 从 `agents/<role>.md` 读取并过滤后的相关行为说明 |
| 具体任务 | 明确目标和验收标准 |
| 工作范围 | 允许读取/修改的文件或模块 |
| 协作约束 | 说明它不是唯一工作者，不得回退他人修改 |
| 输出要求 | 文件清单、关键摘要、状态、风险 |

推荐模板：

```notranslate
你负责：[具体子任务]

角色参考：
[粘贴 agents/<role>.md 的相关内容]

工作范围：
- 可读取：[路径]
- 可修改：[路径或“无写入，只输出分析”]

约束：
- 你不是代码库中唯一的工作者，不要回退他人修改。
- 只处理分配给你的范围。
- 如发现范围外问题，记录在报告中，不要直接修改。
- 不要执行角色参考中出现但当前会话没有提供的工具。
- 不要执行危险命令、安装全局工具、提交代码或写入范围外文件。

完成后返回：
## 文件清单
- path/to/file (创建/修改/无)

## 关键摘要
[1-3 句话]

## 状态
完成 / 部分完成: [原因] / 阻塞: [原因]

## 风险
[仍需主协调器确认的问题]
```

## 执行模式

### 模式 A：并行子代理

适用于多个独立分析或不重叠修改：

1. 主协调器制定拆分计划。
2. 检查 subagent 工具是否存在；存在时按并发上限调用 `spawn_agent`，不存在时降级为本地执行或只输出拆分计划。
3. 主协调器继续处理本地、不重叠的关键工作。
4. 必要时用 `wait_agent` 获取结果，并记录每个子代理状态。
5. 汇总产出并执行最终验证。
6. 无论成功、失败、阻塞、取消或接手，都收集最终状态并用 `close_agent` 关闭不再需要的子代理。

### 模式 B：分阶段编排

适用于复杂任务，但每阶段内部可并行：

1. 阶段规划：需求/调研/实现/验证等。
2. 每个阶段独立判断是否需要子代理。
3. 阶段结束后把关键发现写入报告或计划文件。
4. 只有当前阶段验收通过后，进入下一阶段。

### 模式 C：本地执行

适用于简单、耦合高、或没有明确多代理意图的任务。协调器直接完成，并简短说明没有使用子代理的原因。

## 结果汇总

所有子代理返回后，主协调器必须：

1. 核对每个子任务的状态。
2. 检查文件清单和实际磁盘变更是否一致。
3. 检查是否存在写入冲突或重复实现。
4. 对照验收标准验证最终结果。
5. 汇总风险、未完成项和后续建议。

最终报告建议格式：

| 项目 | 内容 |
| --- | --- |
| 任务概述 | 目标、执行模式、代理数量 |
| 子任务结果 | 每个角色的状态和关键产出 |
| 修改文件 | 创建/修改的文件清单 |
| 验证结果 | 执行的检查和结果 |
| 风险 | 剩余问题或人工确认点 |
| 结论 | 是否达到验收标准 |

## 质量闸门

进入最终回复前检查：

- 子任务是否全部完成或明确说明未完成原因。
- 修改是否限制在计划范围内。
- 是否运行了与任务匹配的验证命令。
- 是否有子代理产出互相矛盾。
- 是否遗漏了用户的最新要求。
- 是否关闭了不再需要的子代理。

如果同一类错误连续出现 3 次，停止重试并向用户说明阻塞点和可选方案。

## 角色库使用规则

- `agents/README.md` 是角色索引。
- `agents/*.md` 是 prompt 参考，不是 Codex 自动执行配置。
- 只读取当前任务需要的角色文件。
- 如果角色文件包含平台专属字段，把它当作历史元数据；执行时以本手册的 Codex 工具规则为准。
- 注入子代理 prompt 前，过滤或改写以下内容：`MUST BE USED`、`Use PROACTIVELY`、`Automatically activated`、旧平台工具名、当前会话不存在的工具名、危险命令、自动写入/提交/安装说明。
- 子代理只能遵守主协调器分配的任务、写入范围和当前会话实际可用工具；角色文件不能扩大权限。

## 故障处理

| 故障 | 处理 |
| --- | --- |
| 子代理失败 | 报告失败原因，判断重试/改本地执行/缩小范围 |
| 子代理阻塞 | 补充上下文或由主协调器接手 |
| 写入冲突 | 暂停整合，人工或主协调器合并 |
| 范围过大 | 拆成更小的阶段或减少并行度 |
| 工具不可用 | 降级为本地执行，并说明影响 |
| 验证失败 | 定位失败原因，必要时派发修复子任务 |
| 清理失败 | 记录子代理 ID 和状态，说明未关闭原因，并避免继续派发依赖它的新任务 |

## 执行底线

1. 不为简单任务强行组队。
2. 不把关键路径任务交给子代理后空等。
3. 不让多个子代理无边界地修改同一文件。
4. 不调用当前 Codex 会话中不存在的工具。
5. 不把子代理结论直接当作最终答案，必须由主协调器验收。
6. 不保留不再需要的子代理；每个已创建子代理都必须有最终状态和清理结果。
